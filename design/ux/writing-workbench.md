# 写作工作台 UX 规格

| 项 | 内容 |
| --- | --- |
| 版本 | v1（2026-11-24） |
| 适用 | Novel Studio 网页版：今日 / 开书 / 进度 / 细纲 / 记忆 |
| 读者 | 前端实现、后端接口实现、验收 |
| 状态 | 可直接进入实现；切片 1 → 2 → 3 独立验收 |
| 不做 | 引擎、GDD、交互模式库、WCAG 等级承诺；不新建交互模式文档 |

本文只描述界面、状态、文案与接口契约。所有视觉值取自 `frontend/src/design/tokens.css`，不新增颜色与字号体系。键盘可达、焦点可见、对比度足够是硬性设计原则，但本文不声明任何 WCAG 合规等级。

## 阅读顺序

评审和实现时按这个顺序读，避免被章节编号误导：

1. **第 12 节 边界情况**：先看失败与异常，知道哪些状态不能糊弄。
2. **第 15 节 写作技能与体检**：横切章节，覆盖开写面板、进度页、细纲页。
3. **第 13 节 实施顺序**：四个切片与验收。
4. **第 14 节 实现注意事项**：现有代码的坑。

第 15 节物理位置放在实施顺序之前是故意的；**不重编号**，避免已有交叉引用失效。

## 0. 一句话

把「写作」从开书流程第 4 步里的一个区间输入框，变成工作台的一等动作：**选章 → 确认文风 → 选写作技能 → 看参考资料 → 整批细纲 + 逐章正文 → 停在待确认 → 体检/按技能改写 → 直接审阅**。同一套选择器同时服务写作与存档；记忆成为可见、可查、可补的前情账，而不是只存在于后端提示词里。

写作技能与体检是横切能力，单列在第 15 节；实施切片见第 13 节。

## 1. 设计原则

1. **一个动作只有一处主入口。** 写作的规范入口是今日页 `开写` 与共享 `WritePanel`；开书第 4 步、细纲页只负责带预设打开它，不另做一套表单。
2. **先确认，再花钱。** 一次开写会触发多次模型调用。开始前必须看见：写哪几章、每章目标、文风、会注入哪些资料、缺什么。
3. **停在待确认，不替作者做决定。** 写作不自动存档；存档是独立的选择动作。
4. **失败不吞章。** 单章失败就停，前文不受影响；失败点可见、可单章重试、可跳过。
5. **记忆可追溯。** 每条摘要、状态、关系都带章号出处，点一下能回到那一章。
6. **缺资料不拦路，但要标灰。** 没有人物卡、没有伏笔、没有记忆都能写；界面明确说清「会弱在哪里」，并给补齐入口。
7. **桌面优先，窄屏降级不阉割。** 记忆页两栏在窄屏变上下堆叠，再窄变标签切换；写作面板在窄屏全屏化。
8. **写作方法可选，不写死。** 去 AI 味、对话打磨、场景落地、章末钩子、连续性、平台打法、虐文公式、文风样本都是开关；默认值按书记住，本批可覆盖。技能不是营销标签，每一项都要说清「做什么、默认开不开、多不多一次模型调用」。

## 2. 信息架构

### 2.1 页面职责边界

| 页面 | 唯一职责 | 不该做的事 | 主要出口 |
| --- | --- | --- | --- |
| 今日 `/overview` | 判断「现在做什么」，一键开写 | 不逐章编辑、不批量存档、不改文风默认 | WritePanel、进度、伏笔、细纲 |
| 开书 `/workflow` | 一次性搭骨架：大纲/世界观 → 设定 → 伏笔 | 不再内嵌写作表单；第 4 步只做开写启动器 | WritePanel、设定、伏笔 |
| 文风 `/style` | 维护全书默认文风、套用作家参照 | 不在这里开写、不逐章覆盖 | WritePanel（本批确认）、设定 |
| 进度 `/progress` | 逐章审阅、体检、**选择并存档/退回** | 不再提供「写作」入口（只做失败重试跳回） | 细纲、废章、记忆出处 |
| 细纲 `/detail` | 段落纲规划、查看每章参考资料与体检、按段开写 | 不改文风默认、不批量存档 | WritePanel（预设本段）、ReferencePanel、ChapterCheckPanel |
| 大纲 `/outline` | 结构大纲（全书层/卷）与世界观两栏，同一次生成 | 不编辑正文 | 细纲、设定 |
| 记忆 `/memory` | 只读回查时间线与叙事记忆；补写缺口 | 不手写记忆、不编辑正文、不在这里改设定 | 进度（章号出处）、设定/人物 |
| 设定 `/setup` | 硬规则、势力、时间线、悬而未决的事 | 不在这里开写、不再放文风编辑 | 开书、文风、记忆 |

### 2.2 跳转关系

```
今日 ──开写──▶ WritePanel ──开始写──▶ 运行视图 ──逐章审阅──▶ 进度(选中本批)
  │                  ▲                                      │
  ├─开书流程─────────┘（第4步启动器）                       ├─存档/退回（批量选择）
  ├─规划下一段──▶ 细纲 ──开写本段──▶ WritePanel             ├─章号出处──▶ 记忆
  ├─到期伏笔──▶ 伏笔 ──带上这条开写──▶ WritePanel           └─去重写──▶ 细纲
  └─记忆缺口──▶ 记忆 ──补生成──▶ 记忆生成视图
```

### 2.3 侧栏顺序与命名

保持五组。文风属于工作台（写正文前要定写法），世界观并进大纲第二栏，不再单列页面：

| 组 | 顺序 | 名称 | glyph | 快捷键 | hint（建议） |
| --- | --- | --- | --- | --- | --- |
| 工作台 | 1 | 今日 | ◐ | h | 现在该做什么 |
| 工作台 | 2 | 开书 | ✍ | n | 大纲 → 设定 → 伏笔 → 开写 |
| 工作台 | 3 | **文风** | ✎ | **w** | **默认写法 · 作家参照** |
| 写作 | 4 | 进度 | ▦ | p | 逐章审阅、选择存档 |
| 写作 | 5 | 废章 | ⌫ | x | 退回与作废的旧稿 |
| 规划 | 6 | 大纲 | ≡ | o | 结构大纲 · 世界观 |
| 规划 | 7 | 细纲 | ☰ | d | 段落纲 · 本章资料 |
| 规划 | 8 | 伏笔 | ◇ | f | 埋了什么，什么时候收 |
| 资料 | 9 | 人物 | 人 | c | 谁在推动故事 |
| 资料 | 10 | **记忆** | ◷ | **m** | **时间线 · 前情 · 回查** |
| 资料 | 11 | 设定 | ⚙ | s | 硬规则 · 势力 |
| 系统 | 12 | 设置 | ⋯ | , | 模型 · 存档 · 修复 |

旧链接 `/world` 重定向到 `/outline?tab=world`，外部书签不失效。

「记忆」徽标规则：当「有正文但没记忆」的章数 > 0 时，显示该数量（中性色，不要用粉色，粉色只属于待确认）；全部回写后不显示。

### 2.4 去重规则（实现必须遵守）

| 动作 | 唯一实现位置 | 其他页面怎么做 |
| --- | --- | --- |
| 写作 | `WritePanel.vue` + `useStudio.startWriteBatch` | 开书第 4 步、细纲页只调用 `openWritePanel({ preset })` |
| 存档 | 进度页 `ArchiveBatchBar` + `useStudio.archiveSelected` | 今日「存档全部待确认」调用同一 store 动作，不复制逻辑 |
| 文风编辑 | 文风页 `/style` | 设定页只放入口；写作面板只做本批覆盖（预览/套预设都不写书默认） |
| 参考资料查看 | `ReferencePanel.vue`（细纲页与 WritePanel 共用内容组件） | 写作面板嵌入 `ReferenceChecklist`，不另写一套 |
| 记忆回写 | 后端 `memory_gen.auto_write_back`（正文/改写落盘后） | 记忆页只读 + 补缺口；写作页只展示回写结果与「待补」提示 |

### 3.2 状态与反馈词表

所有异步动作必须有四种可见状态：**空 / 加载 / 部分失败 / 全失败**。本应用没有角色权限，因此不写「无权限」；只保留文件系统权限错误的提示。

| 状态 | 视觉 | 文案规则 |
| --- | --- | --- |
| 加载 | 骨架行或按钮内「正在…」 | 超过 8 秒补一行「模型可能还在生成，别关页面」 |
| 空 | `NsEmptyState` 或行内灰字 | 说清「为什么空」和「下一步点哪」 |
| 部分失败 | 列表内单行 bad + 顶部汇总条 | 保留已成功项，不整页报错 |
| 全失败 | `NsEmptyState` + 重试按钮 | 给原始原因，不写「系统错误」 |
| 崩溃/刷新 | 恢复条 | 只提示「检查第 N 章」，不自动重试 |

进度条动画遵循 `prefers-reduced-motion`；状态不得只靠颜色区分，必须同时有文字标签。

### 3.3 焦点与键盘总则

- 所有可交互元素原生可达；禁止 `outline: none` 且无替代。焦点环使用 `--ns-focus`，并用 1px `--ns-pink` 描边确保深浅色都可辨。
- 打开 `WritePanel` 后焦点进入对话框；`NsModal` 需要补焦点陷阱、首个焦点、关闭后焦点回到触发按钮。`Esc` 关闭；运行中 `Esc` 只收起面板，不取消本批。
- 模态内的 `J/K/Space/Shift` 只在面板内生效；输入框聚焦时不抢键。
- 运行状态用 `role="status" aria-live="polite"`；失败用 `role="alert"`。
- 最小点击高度：桌面 28px（`sm`），主按钮 34px；行内 checkbox 点击区至少 28×28。
- 字号：正文最小 12px；辅助说明 11px；不使用 10px 以下承载必要信息。数字使用 tabular-nums。

### 3.4 响应式断点

| 断点 | 写作面板 | 记忆页 | 进度批量条 |
| --- | --- | --- | --- |
| ≥ 1100px | 两栏：章节 55% / 设置 45% | 两栏 1.15fr / 0.85fr | 单行工具条 |
| 760–1099px | 单栏顺序：章节 → 设置 → 文风 → 资料 | 上下堆叠：时间线 → 叙事记忆 | 工具条换行 |
| < 760px | 全屏模态（100% 宽高、无圆角） | 顶部标签切换「时间线 / 叙事记忆」 | 只留「选择」与「存档」两个主按钮 |

### 3.5 性能与分辨率验收

测试条件：本地开发环境、暖缓存、一本书 100 章 / 10 卷、10 章运行列表；测量从点击到「首屏可交互」，不是等全部数据。首屏定义：面板/页面的标题、工具条、前 10 行可操作。

| 面 | 预算 | 说明 |
| --- | --- | --- |
| 开写面板打开 | ≤ 200ms | 章节与设置来自已加载的 store；文风/技能/资料可先骨架，后到不阻塞选章 |
| 参考资料首屏 | ≤ 300ms | 先出 6 个分组标题与条数；预览文本可延迟 100ms 内补齐 |
| 记忆页首屏 | ≤ 400ms | 先出工具条 + 当前卷前 10 行 + 覆盖度；卷摘要与人物卡随后 |
| 10 章运行列表滚动 | 不掉帧 | 60fps；不因每章状态更新触发整页重排；单行高度固定 |
| 体检面板打开 | ≤ 150ms | 先用缓存结果；无缓存时先骨架，确定性体检 ≤ 5s 完成 |
| 批量选择 100 行 | ≤ 100ms | 全选/清空/范围选择不逐个触发网络请求 |

验收分辨率：**1024×768、1440×900、1920×1080**；窄屏 **768×1024**。每个分辨率检查：无横向滚动、首屏操作可见、长文案不挤出容器、运行列表可滚动到完成态。

- 超过 100ms 的等待必须有骨架或行内 loading；不允许白屏。
- 任何筛选/勾选交互不得等网络；本地状态先变。
- 首屏预算不达标时，优先拆请求（章节/设置/资料分开），不要给列表加虚拟滚动掩盖。

### 3.6 动效与减动效

| 动效 | 时长 | 曲线 / 说明 |
| --- | --- | --- |
| `WritePanel` 进入 / 退出 | 120–160ms | 透明度 + 4px 位移；不缩放 |
| `RunMiniBar` 滑入 / 滑出 | 160ms | 从底部 8px 滑入；不遮挡操作 |
| 运行中状态脉冲 | 1.2s 循环 | 只改透明度，不改尺寸；一次只脉冲一个当前章 |
| 进度条宽度变化 | ≤ 250ms | 不因每章完成而闪跳 |
| 体检分类展开 | 120ms | 高度过渡或瞬时；不阻塞点击 |

- `prefers-reduced-motion: reduce` 时：所有过渡时长设为 0，去掉位移、缩放、脉冲；运行中状态改为静态圆点 + 文字 `进行中`。
- 动效不得阻塞操作：面板打开动画期间可以点选章节；运行列表更新不影响滚动位置。
- 不做闪烁、频闪、自动播放的装饰动画。进度条只表示真实状态，不做无限循环的假进度。

### 3.7 本地化与截断

- 按钮文案 **≤ 8 个汉字**；标签 **≤ 6 个汉字**；状态短语 **≤ 10 个汉字**。超出的说明放 `hint`、`title` 或展开区，不塞进按钮。
- 例外：模态标题、页面标题、正文说明不受此限；命令面板条目可到 14 字；带章号的上下文按钮（如「按技能改写第 14 章」）可到 12 字，窄屏必须降级为短文案「按技能改写」。
- 书名、章名、人名在列表内**单行省略**（`text-overflow: ellipsis`），`title` 或可聚焦 tooltip 显示全称；不允许把状态标签挤掉。
- 状态标签不截断；宽度不够时换行到第二行，或把数值收进 `title`。
- 窄屏（<760px）顶部标签只留 **图标 + 2 字**：`◷ 时间线`、`▤ 记忆`；完整名称放 `aria-label` 与 `title`。
- 中文不需要按 40% 膨胀预留；但长英文单词、URL、连续数字必须 `overflow-wrap: anywhere`，避免撑破卡片。
- 数字用 tabular-nums；千分位在字数、tokens 使用 `2,380`，章号保持 `012` 补零。
- 所有截断都要有替代获取全文的路径：hover、focus、展开、或点进详情。

## 4. 屏幕 S1：开写面板（今日页核心）

### 4.1 目标

让作者在 15 秒内确认「写哪几章、写成什么样、会带哪些前情」，然后启动一次可观察、可中断、可单章重试的批量写作。

### 4.2 进入路径与优先级

**作者到达状态**：刚在今日页看完任务队列（或刚打开应用），手上没有未保存的正文；可能刚在设定页改过文风默认，但本批还没确认。来源：今日 PageHeader/任务队列、开书第 4 步、细纲「开写本段」、到期伏笔任务、命令面板。面板内的文风/技能覆盖是临时态，关闭即丢弃。

**今日页**

1. `PageHeader` 右侧常驻主按钮：`✒ 开写`。无大纲时禁用，`title="先立大纲和世界观"`。这是所有状态下写作的第一入口，不随任务队列消失。
2. Hero 主按钮按优先级：
   - 无大纲 → `生成大纲和世界观`
   - 无正文 → `开写第 1–10 章`
   - 有待确认 → `确认第 N 章`（写作仍由 PageHeader 的 `开写` 直达）
   - 有到期伏笔且无待确认 → `带上到期伏笔开写`（打开面板并预设 focus）
   - 其余 → `开写第 N 章`
3. 「现在做什么」队列：
   - 待确认任务：`处理第 N 章`（primary）、`接着写下一章`（ghost）、`存档全部`（secondary）。三个动作封顶。
   - 到期伏笔任务：`带上这条开写`（primary）、`去收线`（secondary）。打开面板时 focus 预置该伏笔。
   - 无卡点时：`开写第 N 章`。
4. 侧栏底部「下一步」：无待确认/到期时，文案改为 `写第 N–M 章`，点击直接开面板，不再跳开书/细纲。
5. 命令面板新增动作：`开写第 N 章`（group「动作」，glyph ✒），以及 `开写…（选范围）`。

#### 分批细纲与每章状态机

细纲按批生成：本批（如第 12–21 章）先一次出一份主线 + 每章节拍，整批共用；正文仍逐章写。

```
本批 → batch_outlining → batch_outline_done
每章 queued → drafting → [deai_scanning → deai_rewriting] → committing → pending_review
                    ↘ failed(stage)
failed → retrying → drafting / deai_scanning / committing
```

方括号内只在「去 AI 味」开启且命中时出现；未命中直接进入落盘。

| 阶段 | 标签 | 说明 |
| --- | --- | --- |
| 本批细纲 | `生成本批细纲…` | 每批一次 outline 接口，覆盖本批所有章 |
| 细纲 | `细纲 ✓` | 行内只显示状态；单章重试时才会单独重出这一章 |
| 正文 | `写正文…` | 调用 prose 接口 |
| 去 AI 味 | `扫描 AI 痕迹…` / `改写一次…` | 仅技能开启时；最多 1 次改写 |
| 落盘 | `落盘中…` | 服务端写文件与索引，通常 <1 秒 |
| 完成 | `已完成 · 2,380 字 → 待确认` | 不自动存档 |
| 跳过 | `已跳过 · 已有正文` | 默认策略 |
| 失败 | `失败 · 停在「正文」` | 展开显示原因；去 AI 味失败不整章失败时标 `去 AI 味未完成` |

#### 运行中的按钮

- `收起（后台继续）`：关闭模态，显示 `RunMiniBar`；不取消。
- `本章完成后暂停`：设置 `pauseAfterCurrent=true`；按钮变 `已安排暂停`，请求完成后不再开始下一章。
- 运行中不可关闭模态（✕ 等同收起）；`Esc` 同理。
- 失败时按钮：`只重试这一章`（primary）、`跳过并继续`（secondary）、`停止本批`（ghost/danger）。
- 全失败：`重试失败章节`、`查看原因`、`关闭`。

#### 完成态

| 结果 | 标题 | 说明 | 按钮 |
| --- | --- | --- | --- |
| 全部成功 | `本批完成` | `新写 3 章，跳过 2 章。都停在待确认，不会自动存档。` | `逐章审阅`（primary）、`继续开写`、`关闭` |
| 部分失败 | `完成 2 章，1 章失败` | `第 13 章停在「正文」：模型超时。本章没有落盘。` | `重试第 13 章`、`逐章审阅`、`关闭` |
| 全部失败 | `这一批没有写成` | 第一条失败原因 + `前面的章没有改动。` | `重试`、`关闭` |
| 全部跳过 | `没有需要写的章` | `选中的章都已有正文。要重写请在设置里选「覆盖」。` | `返回修改`、`关闭` |

## 5. 屏幕 S3：进度页的存档选择

### 5.1 目标

把「逐章点存档」升级为「勾选一批 → 批量存档或退回」，同时不让自动存档与手动选择互相打架。

### 5.2 进入路径

**作者到达状态**：刚写完一批（停在待确认）、刚退回过一章，或从今日/命令面板来；手上没有未保存的正文（进度页只读）；可能有未提交的批量勾选，刷新即清。

- 侧栏 `进度`。
- 今日待确认任务的 `存档全部`（快捷动作，等价于全选待确认 + 批量存档）。
- 写作完成的 `逐章审阅`。
- 命令面板 `存档待确认`。

### 5.3 线框

```
┌ 进度 ──────────────────────────────────────────────────────────┐
│ 本批 012–021 · 手动模式：勾选章节后批量存档        [按批体检] │
├ 选择工具条 ────────────────────────────────────────────────────┤
│ ☑ 已选 3 章  [全选待确认] [全选本章段] [清空]                  │
│ [✓ 存档选中 3 章] [↩ 退回选中 3 章]       J/K 走章 · 空格勾选  │
├ 列表 ──────────────────────────────────────────────────────────┤
│ ☑ 012 ─ 标题 ─ 2,380 字 ─ [待确认] ─ …                         │
│ ☐ 013 ─ 标题 ─ 2,410 字 ─ [待确认] ─ …                         │
│ ☑ 014 ─ 标题 ─ 2,200 字 ─ [已存档] ─ …                         │
└────────────────────────────────────────────────────────────────┘
```

### 5.4 选择规则

- 每行左侧新增 checkbox；整行点击仍展开正文，checkbox 点击不展开。
- 只能选「有正文」的章；无正文行 checkbox 禁用，`title="这一章还没有正文"`。
- `全选待确认` 选所有 `!approved` 且有正文的章。
- `全选本章段` 选当前段落范围内的可存档章。
- `清空` 只清选择，不重置筛选。
- 选中后工具条显示 `已选 N 章`；按钮括号内数字同步。
- 筛选切换不丢选择；被筛选隐藏的已选章仍计入，并在工具条提示 `含 2 章不在当前筛选`。

### 5.5 批量存档

- 点击 `存档选中 N 章` 调 `POST /projects/archive-batch`。
- 成功：逐章移除选择、行状态变已存档、Toast `已存档 3 章`。
- 部分失败：保留失败章选中，顶部出现结果条：
  `已存档 2 章；第 13 章还有 3 条硬伤` + `查看` + `仍然存档这 1 章`。
- 全部失败：结果条 + `查看问题`；不弹整页错误。
- 硬伤详情沿用现有 `blocked` 模态，但支持多个失败章：一次列出全部失败章的 findings，底部 `仍然存档 N 章`。
- 幂等：已经存档的章返回 `skipped:true`，界面视为成功，不报错。

### 5.6 批量退回

- 点击 `退回选中 N 章` 先弹确认：
  - 标题 `退回 3 章？`
  - 说明 `旧稿会进「废章」，章号释放，可以立刻重写。这个动作不会自动重写。`
  - 输入可选的 `退回原因`（单行，最多 80 字）。
  - 按钮 `取消` / `退回 3 章`（danger）。
- 结果逐章返回；失败（例如章已被删除）单独列出，保留选中。
- 退回后当前段状态重算，Toast `已退回 3 章，旧稿在「废章」`。

### 5.7 autoArchive 与手动选择的关系

`prefs.autoArchive` 保持默认关闭（现状即默认关）。文案与行为必须一致：

| 场景 | 行为 |
| --- | --- |
| 设置开关关 | 进度页不自动存档；顶部说明 `手动模式：勾选章节后批量存档。` |
| 设置开关开，直接进入页面 | 进入后自动存档所有待确认章（逐章过体检）；顶部说明 `自动存档已开：进页面会存档待确认章。` |
| 设置开关开，带 `?chapter=` 进入 | 不自动存档（明确来审这一章） |
| 设置开关开，用户勾选了任意章 | 本次访问暂停自动存档；说明变 `自动存档已在本页暂停：你正在手动选择。`；刷新后恢复 |
| 自动存档遇到硬伤 | 停在第一个硬伤章，弹现有 blocked 模态；其余待确认保持原样 |
| 开关切换 | Toast `自动存档已开启，下次进进度页生效` / `已关闭，改为手动选择`；不立即触发存档 |

设置页开关文案改为：

- 标题 `进入进度页自动存档`
- 说明 `开启后，进入「进度」页会自动存档待确认章；你在页面上勾选章节时，本次自动存档暂停。默认关闭。`
- 状态 Tag：`手动优先`（关）/ `自动（可被手动打断）`（开）

### 5.8 键盘

| 键 | 行为 |
| --- | --- |
| `J` / `K` | 下一章 / 上一章（移动 active row，滚动到可见） |
| `Space` | 勾选/取消当前章 |
| `Shift + J` / `Shift + K` | 从锚点到当前章连选；锚点为上次 Space 或点击的章 |

### 5.9 文案

- 工具条：`已选 3 章`、`全选待确认`、`全选本章段`、`清空`、`存档选中 3 章`、`退回选中 3 章`

- 全失败：`这一批没有存档成功` / `原因：第 13 章有 3 条硬伤，第 14 章不存在。`
- 退回确认：`退回 3 章？` / `旧稿会进「废章」，章号释放，可以立刻重写。这个动作不会自动重写。`

### 6.2 进入路径

```
┌ 设定 / 文风 ──────────────────────────────────────────────────┐
```

### 6.4 字段定义

| 字段 | 键 | 类型 | 选项 / 限制 | 注入位置 |
| --- | --- | --- | --- | --- |
| 视角 | `pov` | 单选 | 第三人称限制 / 第一人称 / 第三人称全知 / 自定义 | 细纲 + 正文 |
| 叙述人称 | `person` | 单选 | 他/她 / 我 / 自定义 | 细纲 + 正文 |
| 句长 | `sentence` | 单选 | 短句为主 / 长短交错 / 长句铺陈 | 正文 |
| 段落长度 | `paragraph` | 单选 | 1–3 句 / 3–5 句 / 长段 | 正文 |
| 节奏 | `rhythm` | 单选 | 紧 / 缓 / 张弛 | 细纲 + 正文 |
| 对话比例 | `dialogue` | 单选 | 低 10–20% / 中 20–40% / 高 40%+ | 正文 |
| 禁用表达 | `banned` | 字符串数组 | ≤30 条，每条 ≤40 字，自动去重 | 细纲 + 正文 |
| 样章 | `samples` | 对象数组 | ≤3 段；`label` ≤12 字，`text` ≤800 字 | 正文（最多注入前 2 段） |
| 参考作者/作品 | `references` | 对象数组 | ≤5 条；`author`、`work`、`note` 各 ≤40 字 | 正文（只注入风格描述，不注入原文） |
| 补充说明 | `notes` | 文本 | ≤500 字 | 细纲 + 正文 |
| 兼容字段 | `tense` | 文本 | 旧数据保留，迁移到 `person` 的补充说明 | 不单独展示 |

存储：`bible.json` 的 `style` 对象，`version: 2`。旧字段 `pov/tense/samples/banned/notes` 原样兼容；新字段缺省为空，不阻塞加载。

### 6.5 三处一致性

| 入口 | 能力 | 显示 |
| --- | --- | --- |
| 设定页「文风」 | 编辑书默认、保存 | 完整字段；脏状态提示 |
| 开写面板「文风确认」 | 确认 / 本批覆盖 / 另存为默认 | 摘要 + 覆盖 chips；`StyleFields` compact |
| 细纲页参考面板 / 运行态 | 只读，看实际生效值 | `StyleAppliedBar`：`书默认` 或 `书默认 + 本批覆盖（节奏、禁用+2）` |

规则：

- 三处使用同一个字段顺序、同一套标签、同一份 `StyleDoc`；不允许在写作面板里另存一份。
- 「本次覆盖」只在当前 `WritePanel` 生命周期与当前运行内有效；关闭面板即丢弃，除非点了「另存为书默认」。
- 运行中的实际生效值冻结在启动那一刻；运行中改设置页不影响本批。

### 6.6 覆盖的回显与清除

- `StyleAppliedBar` 摘要：`书默认：第三人称限制 · 他/她 · 短句为主 · 张弛 · 对话 20–40%`。
- 有覆盖时追加 `＋ 本批：节奏=紧、禁用表达 +2`。
- 覆盖 chips 单项 `×` 清除；`重置本次覆盖` 全清。
- 若覆盖值等于书默认值，不显示该 chip（避免噪声）。
- 「另存为书默认」弹确认：`把本次改动存为书默认？` / `以后每次开写都会带上；只影响这本书。`

### 6.7 状态与文案

- 空：`还没填文风` / `不填也能写，但句长、对话比和禁用表达会按平台默认。` / `用 AI 从设定里补一版`（调用现有 `generateSettings`，只补空字段）。
- 加载：骨架三行；保存中按钮 `保存中…`。
- 部分失败（保存时后端某字段校验失败）：字段下方红字，保留其他编辑。
- 全失败：`保存失败：{原因}` + `重试`；不丢本地编辑。
- 成功 Toast：`文风默认已保存`。
- 脏状态：页脚 `有未保存的改动` + 离开确认 `离开会丢掉这次修改。`
- 只读：无权限概念，不适用。

### 7.4 左栏：时间线

**分组**

- 按卷折叠；默认展开「包含当前写作章」的卷，其他卷折叠。
- 无卷索引时按 50 章一组，组名 `第 1–50 章`。
- 单卷内按章号升序；章行之间用竖线连接，形成时间轴。

**单章行字段**

| 字段 | 展示 | 缺失时 |
| --- | --- | --- |
| 章号 | `003` 等宽 + `第 3 章` | — |

| 伏笔 | `埋 · 铜钥匙`、`收 · 旧照片` | 不显示 |
| 状态变化 | `阿枝：信任 → 戒备` | 不显示 |
| 出处 | `去这一章 →` | — |

**整行交互**

- 点击行 → 右栏滚动到该章摘要并高亮。
- 行内 `去这一章 →` → `progress?chapter=N`。
- 展开/收起：事件超过 3 条时 `展开全部`；卷头可折叠。
- 行不接受拖拽、不就地编辑。

**生成缺口**

- 没有记忆但有正文的章：行仍显示（章号 + 标题 + `还没生成记忆`），右侧灰字 `生成`。
- 完全没有正文：`NsEmptyState`。
- 顶部覆盖度条：`已生成 12/23 章`；点击展开缺失章号列表。

### 7.5 右栏：叙事记忆

顶部 segmented control：`卷摘要 / 人物 / 关系 / 回查`。默认 `卷摘要`。章摘要不单独占 tab，作为卷摘要下方的连续列表，保证阅读连贯。

#### 卷摘要

- 当前卷置顶：标题、章范围、摘要全文、六个维度（只显示非空）：`主线`、`支线`、`关系`、`读者已知`、`带出下一卷`、`与大纲偏差`。
- 每个维度一行 `dt/dd`，最多 4 行，超出 `展开`。
- 卷摘要底部：`覆盖第 1–12 章 · 生成于 2026-11-20` + `重新生成`。
- 下面接章摘要列表：按章倒序（最新在上）或正序？**正序**，因为前情是时间线叙事；默认滚动到当前章。每条：章号、标题、摘要、`关键事件` 前 2 条、`去这一章 →`。

#### 人物

- 人物选择器（搜索 + 列表），默认选「本章出场最多」或第一个主角。
- 人物卡：姓名、状态 Tag（`在场` / `已死亡` / `失踪` / `离场`）、`截至第 N 章`。
- 三块：
  - `知道什么`：`第 3 章知道：…`，最多 4 条，带章号。
  - `关系`：`与阿枝：师徒但彼此提防（第 3 章）`，最多 4 条。
  - `最近变化`：`第 5 章：从「信任」变「戒备」`。
- 空：`这个人物还没有状态记忆` / `生成记忆后，会显示他截至当前章知道什么、和谁是什么关系。`

#### 关系

- 边表：`A ↔ B`、当前状态、最后变化章、`去这一章 →`。
- 支持按人物过滤（复用顶部人物筛选）。
- 空：`还没有关系变化记录`。

#### 回查

- 输入框 `⌕ 输入人名、地点、物件、伏笔名（至少两个字）` + `回查`。
- 结果：`命中 8 处，按相关度显示前 6 处`。
- 每条：`第 3 章《标题》[原文/记忆/伏笔账/细纲]` + 引文 + `去这一章 →`。
- 无结果沿用后端文案：`没找到「…」相关的记忆或正文。换个说法（人名/地点/物件/伏笔名）再查。`
- 查询中：按钮 `回查中…`；结果区保留上一次结果并降低透明度，避免闪空。

### 7.6 筛选

| 筛选 | 类型 | 作用范围 |
| --- | --- | --- |
| 卷 | 单选下拉 | 左栏折叠到该卷；右栏卷摘要切到该卷 |
| 人物 | 单选可搜索 | 左栏只显示该人物出场的章；右栏人物卡切到该人 |
| 地点 | 单选可搜索 | 左栏只显示该地点出现的章 |
| 关键词 | 文本（防抖 300ms） | 左栏匹配摘要/事件/人物/地点；右栏章摘要列表同步过滤 |

- 所有筛选可叠加；`清除筛选` 恢复全部。
- 筛选不触发网络请求（数据已在内存）；关键词回查是独立动作，不复用此输入。
- 空结果：`没有符合筛选的章节` / `清除筛选，或去生成更多记忆。` + `清除筛选`。

### 7.7 生成记忆

**入口**：页头 `从已写章节生成`；缺口条上的 `补齐 11 章`；单章行 `生成`；卷摘要 `重新生成`。

**弹窗**：

```
┌ 生成叙事记忆 ─────────────────────────────────────── ✕ ┐
│ 从已写章节里提炼时间线、事件、人物状态、关系、伏笔埋收。 │
│ 范围  (•) 只补缺失（11 章）  ( ) 第 [1]–[23] 章         │
│       ( ) 只生成卷摘要                                  │
│ [✓] 生成完顺带更新卷摘要                                │
│ 每章一次模型调用，11 章大约 6–12 分钟。                 │
│ [取消]                              [开始生成 11 章]    │
└─────────────────────────────────────────────────────────┘
```

**运行**：

- 逐章调用 `POST /projects/memory/chapter/{n}/generate`；每完成一章，左栏对应行即时出现。
- 顶部进度：`正在生成第 7 章 · 6/11`；可 `暂停（本章完成后）`。
- 部分失败：`已生成 6 章；第 7 章失败：模型超时`；失败章保留在缺口列表，可单击重试。
- 全失败：`这一轮没有生成成功` + 第一条原因 + `重试`。
- 完成：`已生成 10 章记忆、2 卷摘要` / `第 17 章失败，其余已完成。` + `查看失败`、`关闭`。
- 覆盖已有记忆：二次确认 `重新生成 3 章记忆？` / `新结果会覆盖当前显示；旧记录仍保留在 ledger/memory.jsonl，但不再展示。`

**生成规则**

- 只对 `chapters/index.json` 中 `chars > 0` 的章开放；空章禁用。
- 已存档与待确认章都算「已写」，都可以生成；界面上用 Tag 区分。
- 卷摘要只在「该卷至少有一章记忆」时开放；缺章时提示 `这一卷还有 4 章没生成记忆，卷摘要会不完整。`
- 生成不修改正文、不改存档状态。
- 生成顺序按章号升序，保证人物状态递进正确。

### 7.8 窄屏降级

| 宽度 | 布局 |
| --- | --- |
| ≥1180 | 左右两栏；两栏各自滚动；顶部工具条固定 |
| 900–1179 | 上下堆叠；时间线在上，叙事记忆在下；右栏 segmented 保留 |
| <900 | 顶部标签 `时间线` / `叙事记忆`；默认时间线；选中章后切到记忆并高亮；URL 加 `?tab=memory` 可分享 |
| <600 | 章行隐藏地点/人物 chips 的第二行，保留事件与伏笔；`去这一章` 图标化但保留文字 |

### 7.9 状态与文案

| 状态 | 内容 |
| --- | --- |
| 无正文 | `还没有可生成记忆的正文` / `记忆从已写章节里提炼：故事内时间、地点、出场人物、关键事件、伏笔埋收。` / `去开写` |
| 有正文无记忆 | `有 12 章正文，还没有记忆` / `生成后，写新章会自动带上这些前情。` / `从已写章节生成` |

| 全失败 | 空状态 + `重试` + 原因 |
| 只读 | 记忆本身只读；只有生成与回查是动作 |
| 无权限 | 不适用；文件权限错误按普通错误提示 |

## 8. 屏幕 S6：细纲页「本章参考资料」

### 8.1 目标

生成细纲之前就能看见「这次会拿哪些资料」，并允许对本章做小范围强调；生成之后能看到实际注入了什么，避免「模型为什么跑偏」无法解释。

### 8.2 进入路径

- 细纲页 PageHeader：`本章资料` 按钮 → 默认当前段第一章未写章。

- 写作面板的参考资料区：`展开清单` 内每个分组底部 `去细纲页看 →`。

### 8.4 内容规则

- 分组默认展开「结构 / 伏笔 / 前情」，其余折叠；显示条数，不显示全文。

- 「缺失」区只列必填/建议项，按影响排序：人物状态 > 关系 > 势力/地点/物品 > 记忆 > 卷摘要 > 时间线。

- 本章已存在正文：标题旁 `Tag ok 已有正文`；主按钮变 `重写本章…`，点击进入覆盖确认。

### 8.5 本章额外强调

- 选择来源：硬规则、地点、人物、物品、伏笔、记忆章；支持搜索。
- 已选 1–5 条；超出提示。
- 注入说明：`强调项会置顶注入，不替代常规资料。`
- 清除：chip `×`；`清空` 按钮。

### 8.6 生成前与生成后的差异

- 生成前：`GET /projects/chapters/{n}/references` + 本地 focus 预览（`POST .../preview`）。
- 生成后：响应 `references` 返回实际打包结果；ReferencePanel 显示 `实际注入` Tag，并冻结当时条数（即使之后设定改了，也看得到当时用了什么）。
- 差异提示：`生成后新增了 2 条设定，下次生成才会带上。`

## 9. 数据契约

所有路径前缀 `/api`，写操作通过查询参数 `dir` 指定书目录（沿用现有约定）。新增接口的错误体统一为：

```json
{ "detail": { "code": "WRITE_BUSY", "message": "另一个窗口正在写第 13 章", "retryable": true, "findings": [] } }
```

旧接口仍可能返回字符串 `detail`，前端 `ApiError` 已兼容。新接口请使用对象。

### 9.1 文风

#### GET `/projects/style?dir=`

响应：

```json
{
  "style": {
    "version": 2,
    "pov": "第三人称限制",
    "person": "他/她",
    "sentence": "短句为主",
    "paragraph": "1–3 句",
    "rhythm": "张弛",
    "dialogue": "中 20–40%",
    "banned": ["他很难过", "空气仿佛凝固"],
    "samples": [{ "label": "《活着》开场", "text": "……", "note": "余华《活着》第一章 · 出处：https://…" }],
    "references": [{ "author": "示例作者", "work": "示例作品", "note": "冷叙事、短句、少形容词" }],
    "notes": "情绪落在动作上，不写总结句。",
    "tense": "",
    "updatedAt": "2026-11-24T06:20:00.000Z"
  },
  "source": "book"
}
```

`source` 表示当前生效值来自 `platform` 默认还是 `book` 本书设置。

`samples` **不来自设定生成**：拆设定只补 `pov / tense / banned`。样章有两个来源——

1. 选作家预设时，用预设里核对过出处的开篇片段补入或替换（每段 ≤300 字，`note` 写书名与出处链接）；
2. 文风页手填（≤3 段，每段 ≤800 字）。

切换预设时，预设样章会换成新作家的那一段；手动新增或编辑过的样章（`origin=manual`）保留。
开写面板的「本批」预设也带上该作家的样章，避免换了作家、语感参照却没变。`note` 只作出处说明，不进入提示词。

#### PUT `/projects/style?dir=`

请求体：`{ "style": { …同上，version/updatedAt 可省略… } }`

- 成功 200：`{ "ok": true, "style": {…}, "updatedAt": "…" }`
- 400 `STYLE_INVALID`：`{code, message, field}`
- 长度校验：`banned` ≤30 / 每条 ≤40；`samples` ≤3 / 每段 ≤800；`references` ≤5 / 每字段 ≤40；`notes` ≤500。

### 9.2 分步写作（替代一次生成）

保留旧 `POST /projects/chapters/{number}/generate` 作为兼容包装；新界面使用下面两个接口，才能显示真实阶段与单阶段重试。

#### POST `/projects/chapters/{number}/outline?dir=`

请求：

```json
{
  "force": false,
  "styleOverride": { "rhythm": "紧", "banned": ["他很难过"] },
  "focus": [{ "type": "foreshadow", "key": "fs-1a2b3c4d", "label": "铜钥匙" }],
  "runId": "wr-20261124-01"
}
```

响应：

```json
{
  "ok": true,
  "chapter": 14,
  "outline": {
    "chapter": 14,
    "title": "夹层",
    "beats": ["拍1…", "拍2…", "拍3…"],
    "mustInclude": ["铜钥匙的代价"],
    "mustAvoid": ["突然下雨"],
    "openingState": "打铁铺门槛",
    "endingState": "后巷药铺门口",
    "pressure": { "deadline": "天亮前", "stake": "失去铺子", "opponent": "债主" },
    "detail": "## 1. 本章定位…",
    "source": "ai",
    "model": "…",
    "at": "…"
  },
  "references": { "…RefPack，见 9.3…" },
  "styleApplied": { "source": "book+override", "effective": { "pov": "第三人称限制" } },
  "model": "…"
}
```

- 若已有可用细纲且 `force=false`：返回 `reused: true`，不调用模型。
- 404 `CHAPTER_OUT_OF_RANGE`：章号 > `targetChapters` 或 ≤0。
- 400 `NO_OUTLINE`：书没有大纲。
- 409 `WRITE_BUSY`：同一 `dir` 有活动运行；`retryable: true`。
- 502 `LLM_ERROR`：模型失败；不落任何细纲。

#### POST `/projects/outlines/batch?dir=`（流式 `/outlines/batch/stream`）

写作面板的主路径：一批章节一次出细纲，整批共用一条主线，每章一条节拍。

请求：

```json
{ "from": 12, "to": 21, "force": false, "runId": "wr-20261124-01",
  "styleOverride": null, "focus": [] }
```

响应：

```json
{
  "ok": true,
  "from": 12,
  "to": 21,
  "spine": "本批主线：铜钥匙的代价一层层压到打铁铺身上",
  "outlines": [
    { "chapter": 12, "title": "…", "beats": ["…"], "mustInclude": [], "mustAvoid": [],
      "openingState": "…", "endingState": "…", "pressure": {},
      "batchFrom": 12, "batchTo": 21, "batchSpine": "…" }
  ],
  "styleApplied": { "…" },
  "model": "…",
  "reused": false
}
```

- 落盘仍是每章一行 `ledger/outline.jsonl`（带 `batchFrom/batchTo/batchSpine`），正文、参考资料与旧接口都按章读取，不感知批次。
- 整批已有可用细纲且 `force=false`：`reused: true`，不调用模型。
- 模型漏章：502 `LLM_ERROR`，整批不落盘（要么整批可用，要么不用）。
- `to` 超过 `targetChapters` 时按目标章数截断。
- 单章重试仍可调 `POST /chapters/{n}/outline`：已有整批细纲时直接复用，不额外调用模型。

#### POST `/projects/chapters/{number}/prose?dir=`

请求：

```json
{
  "overwrite": false,
  "styleOverride": { "rhythm": "紧" },
  "focus": [],
  "runId": "wr-20261124-01",
  "model": null
}
```

响应：

```json
{
  "ok": true,
  "chapter": {
    "number": 14,
    "title": "夹层",
    "file": "chapters/014-夹层.md",
    "chars": 2380,
    "summary": "……",
    "characters": ["沈默", "阿枝"],
    "approved": false,
    "chapterVerdict": "pass",
    "endHook": { "ok": true, "reason": "" },
    "dialogueRatio": 0.31,
    "committedAt": "…"
  },
  "text": "……",
  "chars": 2380,
  "references": { "…实际注入的 RefPack…" },
  "styleApplied": { "source": "book+override", "effective": { "rhythm": "紧" } },
  "model": "…"
}
```

- 已有正文且 `overwrite=false`：409 `CHAPTER_EXISTS`，`message` 明确「先退回或勾选覆盖」。
- 已有正文且 `overwrite=true`：旧稿写进 `drafts/`，返回 `backupDraft: "drafts/…"`。
- 没有细纲：409 `NO_OUTLINE_ROW`，前端提示先点「生成细纲」。
- 正文 <300 字：502 `PROSE_TOO_SHORT`，不落盘。
- 成功落盘状态一律 `approved: false`（待确认）。

#### 运行并发保护

- `runId` 由前端生成（`wr-{yyyymmdd}-{4位随机}`），随每个请求发送。
- 服务端内存表 `{dir: {runId, chapter, stage, startedAt}}`；同 `dir` 不同 `runId` 且未超时（15 分钟）→ 409 `WRITE_BUSY`。
- 同一 `runId` 重试允许；请求结束释放。
- 重启服务后内存表清空，不做持久化；旧运行由前端快照提示检查。

## 11. 边界情况

| 场景 | 界面表现 | 允许的操作 | 不允许 |
| --- | --- | --- | --- |
| 书没有大纲 | 开写按钮禁用；面板顶部警告条 | `去开书流程` | 调用模型、落空章 |
| 没有世界观 | 参考资料「世界观」缺失灰行；仍可写 | `去世界观页` | 假装有资料 |
| 没有设定（人物/规则/势力） | 警告条「缺人物卡和硬规则」；资料行灰 | `去设定页生成`、`仍然开写` | 自动用空资料硬写且不提示 |
| 没有伏笔 | 「其他未收」灰行；本章应收应埋显示「本章没有」 | 继续写 | 把缺失当错误阻断 |
| 没有段落纲 | 「本章台阶」灰行；写作允许 | `去细纲页规划` | 用上一段台阶冒充 |
| 章节已存在 | 行标 `待确认`/`已存档`；默认不选 | 勾选覆盖 + 二次确认 | 静默覆盖 |
| 已存档章被选中 | 仅在开启覆盖后可选 | 提示旧稿进废章 | 无提示覆盖 |
| 写到一半刷新 | 恢复条：`上次写作在第 N 章中断` | `检查`（跳进度该章）、关闭 | 自动重发请求 |
| 落盘前断网 | 该章失败 `模型超时/连不上后端`；无半截文件 | 重试本章 | 把空章写进索引 |
| 并发点两次 | 按钮立即禁用；服务端 409 | 等待 | 第二次请求真正开跑 |
| 两个标签页同时写 | 后开的标签收到 `WRITE_BUSY` | `刷新查看进度` | 两边都写同一章 |
| 模型超时 | 行停在对应阶段；说明「本章没有落盘」 | 重试、跳过、停止 | 自动无限重试 |
| 细纲 JSON 解析失败 | `细纲没有返回可解析的节拍`；本章未落盘 | 重试、换模型 | 把原文当细纲落账 |
| 正文 <300 字 | `正文过短，未落盘` | 重试、换模型 | 落半成品 |
| 一次选 50 章 | 允许，但提示 `50 章约 2–4 小时` | 开始、改范围 | 静默开跑 |
| 批量存档部分失败 | 成功项已存档；失败项保留选中 | `仍然存档`、`查看问题` | 整批回滚已成功项 |
| 自动存档遇硬伤 | 停在第一个硬伤章，弹 findings | 仍然存档、先改 | 跳过硬伤继续存 |
| 记忆章没有正文 | 行 `生成` 禁用 | — | 生成空记忆 |
| 记忆生成到一半失败 | 已完成章即时可见；失败章保留缺口 | 重试失败章 | 丢掉已完成章 |
| 同一章重复生成记忆 | 二次确认；新行追加，读取取最新 | 确认、取消 | 物理覆盖旧行 |
| 记忆页无卷索引 | 按 50 章分组 | 正常浏览 | 空白页 |
| 文风未填 | 允许按平台默认；面板显示警告 | `使用书默认`（空）、`去设定页` | 阻断开写 |
| 文风保存失败 | 保留本地编辑；字段错误定位 | 重试 | 静默丢弃 |
| 目标字数低于下限 | 警告条；可开写 | 改目标、仍然开写 | 静默不提示 |
| 书目录没有写权限 | 存档/写作返回 403；提示路径 | 换目录/修权限 | 重试风暴 |

刷新恢复的具体规则：

1. `startWriteBatch` 每进入/离开一个阶段写一次快照：`{id, dir, numbers, rows, startedAt, active:true}`。
2. 应用启动或 `openBook` 时读快照；若 `active` 且 `dir` 匹配，标记 `recovered`，不自动继续。
3. 用 `studio.chapters` 对账：快照中 `drafting/committing` 的章若已出现在 index 且 `approved:false`，标 `已完成（已落盘）`；否则标 `中断，未知`。
4. 页面显示 `RunMiniBar` 的恢复态；用户点 `检查` 跳进度页对应章，点 `×` 丢弃快照。
5. 服务端不保存运行队列；前台重试从失败阶段开始，若细纲已存在则跳过 outline。

## 12. 明确不做

以下内容本轮不实现，避免蔓延：

1. **不做正文在线编辑器。** 进度页仍只读 + 复制；改写走「按问题重写」。
2. **不做自动写作守护进程/队列。** 写作由前端逐章驱动；刷新不自动续跑。
3. **不做存档后自动生成记忆。** 记忆生成是显式动作；不在 `archive` 里偷偷调模型。
4. **不做时间线手工编辑。** 时间线由记忆生成器产出；作者要改事实，应改正文或记忆源后再生成。
5. **不做关系图可视化。** 关系只用边表与人物卡呈现。
6. **不做多选人物/地点筛选的复杂布尔组合。** 单人物 + 单地点 + 关键词已够。
7. **不做记忆全文搜索的向量检索。** 沿用现有确定性关键词回查。
8. **不做版本对比/记忆历史回滚。** ledger 保留历史行，但界面只看最新。
9. **不做新的主题、字体、图标体系。** 全部使用现有 token 与组件。
10. **不做 WCAG 等级承诺与无障碍声明页。** 只落实键盘、焦点、对比度、非颜色状态。
11. **不做权限/多用户。** 本地文件应用，无角色概念。
12. **不做移动端专属交互。** 只保证窄屏可用，不设计手势。
13. **不做「AI 一键生成整本文风」。** 文风由设定生成补空或作者手填。
14. **不做导出、封面、发布。** 保持现有范围。

## 15. 写作技能与体检

### 15.1 概念边界：文风是目标，技能是工序

| | 文风（第 6 节） | 写作技能（本节） |
| --- | --- | --- |
| 回答的问题 | 这一批**写成什么样** | 用哪些**方法**写、写完后**检查/加工**什么 |
| 典型字段 | 视角、人称、句长、段落、节奏、对话比例、禁用表达、样章、参考作者 | 去 AI 味、对话打磨、场景落地、章末钩子、连续性、平台打法、虐文公式、文风样本 |
| 存储 | `bible.json` 的 `style` | `project.json` 的 `writingSkills` |
| 覆盖粒度 | 本批字段级覆盖 | 本批开关级覆盖 |
| 生效方式 | 作为提示词的「目标」 | 决定注入哪些方法模块、生成后是否扫描/改写 |
| 不做什么 | 不决定是否后处理 | 不改变视角、句长、对话比例这些目标值 |

举例：文风写「对话比例 20–40%」，技能「对话打磨」决定是否按人物口吻逐句改对话；关掉对话打磨不会把对话比例变成 0。反过来，打开「文风样本」不会自动改视角。

底层提示词模块对应关系（本轮落成 `prompts/` 下的本地模块，不依赖外部服务）：

| 技能 | 复用的方法 / 模块 |
| --- | --- |
| 去 AI 味 | `humanizer`：AI 文风病灶与改写流程；确定性检测复用 `metrics.AI_TELL_RULES` |
| 对话打磨 | `narrative-director` + `writer`：对话策略、潜台词、人物口吻 |
| 场景落地 | `narrative-director` + `writer`：场景目标/阻碍/结果、动作与潜台词 |
| 章末钩子 | `narrative-director`：信息型 / 危险型 / 选择型钩子 |
| 连续性 | `world-builder` + `memory.py`：势力/规则一致性、人物状态、关系、伏笔、时间线 |
| 平台打法 | `platforms.py`：字数、段落、对话比、平台禁忌 |
| 虐文公式 | `prompts/虐文.md` + `nuewen.py`：最 X → 最非 X、因果链、代价落地 |
| 文风样本 | `bible.style.samples`：只作语感参照，不复制原文 |

### 15.2 开写面板：写作技能多选

#### 位置与线框

在「文风确认」之后、「参考资料」之前，作为 ⑤ 区；默认折叠为一行摘要，展开后每项一行。

```
┌ ⑤ 写作技能 ─────────────────────────────── 6 / 8 开 ┐
│ 决定这一批用哪些方法写、写完后检查什么。            │
│ 默认值按书记住；下面的改动只作用于这一批。          │
│ ┌────────────────────────────────────────────────┐ │
│ │ ☑ 去 AI 味        生成后扫 AI 痕迹，命中硬伤时改写一次 │
│ │                   默认开 · 命中时最多 +1 次调用 · 生成后 │
│ │ ☑ 对话打磨        按人物口吻改对话，删解释性对白      │
│ │                   默认开 · 不额外调用 · 正文          │
│ │ ☑ 场景落地        每一拍写成具体场景，不写旁白概括    │
│ │                   默认开 · 不额外调用 · 细纲 + 正文   │
│ │ ☑ 章末钩子        章末留信息/危险/选择型钩子          │
│ │                   默认开 · 不额外调用 · 细纲 + 正文   │
│ │ ☑ 连续性检查      带入人物状态、关系、伏笔、时间线    │
│ │                   默认开 · 不额外调用 · 细纲 + 正文   │
│ │ ☑ 平台打法        按平台字数、段落、对话比、禁忌写    │
│ │                   默认开 · 不额外调用 · 细纲 + 正文   │
│ │ ☐ 虐文公式        按「最 X → 最非 X」推进反转与代价   │
│ │                   未开启虐文模式 · 仅虐文书可开       │
│ │ ☑ 文风样本        把样章作为语感参照                  │
│ │                   默认开 · 无样章时不生效 · 正文       │
│ └────────────────────────────────────────────────┘ │
│ 本批覆盖：关闭「场景落地」                          │
│ 默认值已按书保存        [重置为书默认] [另存为书默认] │
└─────────────────────────────────────────────────────┘
```

#### 技能定义（每项一行：名称、作用、默认、成本、影响步骤）

| 技能 | id | 一句话作用 | 默认 | 是否多一次模型调用 | 影响步骤 |
| --- | --- | --- | --- | --- | --- |
| 去 AI 味 | `deai` | 生成后按 `AI_TELL_RULES` 扫一遍；命中 high 或判定「差」时改写一次 | 开 | **命中时最多 +1 次**；全清则 0 次 | 生成后（正文落盘前） |
| 对话打磨 | `dialogue` | 按人物卡口吻改对话，删解释性对白和「说明式台词」 | 开 | 否 | 正文 |
| 场景落地 | `scene` | 每一拍写成具体场景：谁·在哪·想要·被什么挡住·结果 | 开 | 否 | 细纲 + 正文 |
| 章末钩子 | `hook` | 章末留信息型 / 危险型 / 选择型钩子，不用旁白预告 | 开 | 否 | 细纲 + 正文 + 确定性检查 |
| 连续性检查 | `continuity` | 把人物状态、关系、伏笔、时间线带进上下文，并对照硬规则 | 开 | 否 | 细纲 + 正文 |
| 平台打法 | `platform` | 按平台字数、段落长度、对话比、禁忌写 | 开 | 否 | 细纲 + 正文 |
| 虐文公式 | `nuewen` | 按「最 X → 最非 X」推进反转与代价 | 跟随书：`book.nuewen` 为真才开；否则锁定关 | 否 | 细纲 + 正文 |
| 文风样本 | `styleSamples` | 把 `bible.style.samples` 作为语感参照注入 | 开；没有样章时显示「不生效」 | 否 | 正文（最多注入前 2 段） |

成本汇总出现在页脚：`预计 3 章 · 6 次基础调用 + 最多 3 次去 AI 味改写 · 8–20 分钟`。关掉去 AI 味时改写次数恒为 0。

#### 默认值与覆盖

- 默认值存储在 `project.json` 的 `writingSkills`，按书保存，不写 localStorage。换浏览器打开同一本书，默认值仍一致。
- 首次没有 `writingSkills` 时使用上表默认；`nuewen` 以 `book.nuewen` 为准。
- 面板里的改动进入 `skillOverride`（只存差异）；关面板即丢弃，除非点「另存为书默认」。
- 「另存为书默认」只保存 8 个开关，不动文风、不动模型设置；确认文案：`把这一批的技能选择存为书默认？` / `以后每次开写都会带上；只影响这本书。`
- 覆盖回显：`本批覆盖：关闭「场景落地」、打开「文风样本」`；每项后 `×` 单项恢复书默认；`重置为书默认` 全清。
- 与文风确认互不阻塞：文风需要显式确认；技能读取默认即可直接开始。技能区首次打开时展开一次，之后按本地折叠状态记忆（`sessionStorage` 即可，不写书）。

#### 不可用与冲突

- 非虐文书：虐文行显示 `未开启虐文模式` + `去细纲页开启 →`；checkbox 禁用，不出现「已开」。
- 无样章：文风样本行可开，但右侧显示 `无样章，开启也不生效` + `去设定页贴样章 →`。
- 关闭「连续性检查」时，参考资料区仍可注入记忆（那是作者手动选择），但提示 `连续性技能已关，模型不会主动对照人物状态`。
- 关闭「平台打法」时显示警告：`平台字数/禁忌仍会由体检拦截，但生成时不会主动规避。` 仍然允许关。

### 15.3 体检的呈现

体检分两层，界面必须把「确定性」和「模型语义」分开，不能混成一个「AI 体检」黑箱。

#### 入口

| 位置 | 呈现 |
| --- | --- |
| 进度页每章行 | 状态 Tag 旁增加体检 chip：`体检 2 硬伤`（bad）/ `体检 1 需改`（warn）/ `体检通过`（ok）/ `未体检`（neutral）。点击 chip 打开 `ChapterCheckPanel` |
| 进度页展开区 | 顶部工具行：`体检`、`AI 复检`、`按技能改写`；下方直接嵌 `ChapterCheckPanel`（无需再开模态） |
| 细纲页 | 生成细纲/正文后，台阶章号旁出现 `体检` 按钮；`ReferencePanel` 增加「体检」标签；无正文时禁用并提示 `先写正文再体检` |
| 命令面板 | `体检第 N 章（确定性）`、`AI 复检第 N 章`、`按技能改写第 N 章` |
| 写作完成态 | 失败/完成行提供 `查看体检`；只在章已落盘时可用 |

#### 线框（`ChapterCheckPanel`）

```
┌ 第 14 章 · 体检 ─────────────────────────────────────── ✕ ┐
│ 结论：2 硬伤 · 3 需改 · 4 提醒     [重新体检] [复制问题]   │
│ [确定性体检] [AI 语义复检] [按技能改写]                    │
├ 确定性体检 ────────────────────────────────────────────────┤
│ AI 痕迹：差 · 12 处 · 密度 3.2/千字                         │
│ ▾ 解释情绪            4 次 · 需改                          │
│   「他很难过」        第 3 段 · 第 52 字      [定位]        │
│   「气氛变得沉重」    第 7 段 · 第 118 字     [定位]        │
│ ▾ 章末总结句          2 次 · 硬伤                          │
│ ▾ 不是 A，而是 B      3 次 · 硬伤                          │
│ ▾ 空洞形容词          3 次 · 需改                          │
│ 其他：字数 2,380 ✓ · 章尾钩子 弱 · 对话比 31% ✓            │
├ AI 语义复检 ───────────────────────────────────────────────┤
│ 还没做语义复检。模型会读本章，找吃书、动机、口吻、对话、    │
│ 信息重复、情绪总结。约 1–2 分钟，会记一次用量。             │
│ [AI 复检]                                                   │
└─────────────────────────────────────────────────────────────┘
```

#### 15.3.1 确定性 AI 痕迹

数据来源：`backend/app/domain/metrics.py` 的 `AI_TELL_RULES` 与 `verdict()`；本规格**不新增检测规则**，只规定展示分组与文案。分类 id 以代码为准，下面是当前必须覆盖的类别：

| 分类 id | 展示名 | 典型命中 | 默认严重度 |
| --- | --- | --- | --- |
| `not-x-but-y` | 不是 A，而是 B 对举句 | 对比句式滥用 | 硬伤 |
| `rather-say` | 与其说…不如说 | 解释式对举 | 硬伤 |
| `as-if-density` | 仿佛 / 宛如 / 犹如 密度 | 比喻堆叠 | 需改 |
| `air-froze` | 空气凝固 / 时间静止 | 套话 | 硬伤 |
| `pupil-micro` | 瞳孔微缩 / 眼神一暗 | 模板动作 | 需改 |
| `eyebrow-frown` | 皱眉 | 模板动作 | 需改 |
| `heart-thrill` | 心中一凛 / 心神一震 | 套话 | 需改 |
| `summary-close` | 章末总结句 | 旁白总结、升华 | 硬伤 |
| `triad` | 三连排比 / 三词并列 | 节奏模板 | 提醒 |
| `empty-adj` | 空洞形容词 | 形容词堆叠 | 需改 |
| `eye-cliche` | 眼眸 / 目光深邃 | 眼神陈词 | 需改 |
| `inner-cliche` | 心中一动 / 内心复杂 | 内心套话 | 需改 |
| `explain-emotion` | 解释情绪 | 直接写「他很难过」 | 需改 |

严重度映射：`high` → 硬伤，`mid` → 需改，`low` → 提醒。`metrics.detect_ai_tells()` 目前只返回行号 `line`；切片 4 需补 `paragraph`（空行分段后的段号）与 `offset`（段内字符偏移）。前端在字段缺失时降级为「行号 + 引文搜索」，不得因此不显示定位。

每条分类必须显示四件事：**分类名、次数、样例、定位**。

| 字段 | 展示 | 规则 |
| --- | --- | --- |
| 分类名 | 可折叠行 | 默认展开硬伤，需改/提醒折叠 |
| 次数 | `4 次` | 来自 `aiTells.categories[].count` |
| 样例 | 最多 2 条引文 | `「他很难过」`，超过 40 字截断 |
| 定位 | `第 3 段 · 第 52 字` + `[定位]` | `paragraph` 从 1 开始；`offset` 从段首算 |
| 严重度 | Tag 硬伤/需改/提醒 | 与 `findings.severity` 对齐 |

`[定位]` 行为：关闭体检面板，展开该章正文，把样例文本设为搜索高亮词，滚动到对应段落；找不到精确偏移时按引文在正文中首次出现定位。无法定位时 Toast：`这段在正文里找不到了，可能已被改写。`

顶部结论条同时显示：`AI 痕迹：差`、`总命中 12 处`、`密度 3.2/千字`。其他确定性问题（字数、章尾钩子、对话比、硬规则）用 `RuleChip` 行展示，不与 AI 痕迹混排。

#### 15.3.2 模型语义复检

复用 `POST /projects/chapters/{n}/ai-check`。必须覆盖六类，界面按类分组，每组显示条数与严重度：

| 分组 | code | 找什么 | 文案示例 |
| --- | --- | --- | --- |
| 吃书 | `continuity` | 与前面章节/设定矛盾 | `第 12 章说钥匙在阿枝手里，本章沈默却从自己口袋拿出` |
| 动机 | `motivation` | 角色为什么此刻做，缺压力/代价 | `沈默突然答应帮忙，但本章没有给出他非帮不可的理由` |
| 口吻 | `voice` | 说话不像人物卡 | `阿枝本章的台词像旁白，不像她的短句和回避` |
| 对话 | `dialogue` | 对话不推进、信息重复、说明式台词 | `第 5–8 段的对话重复了第 3 段已经交代的信息` |
| 信息重复 | `repetition` | 同一信息换说法反复说 | `铜钥匙的来历在三段里解释了三次` |
| 情绪总结 | `emotion-summary` | 用总结句代替动作/细节 | `「他心里五味杂陈」没有落到具体动作` |

每条显示：严重度 Tag、问题、建议（`hint`）、`定位到正文`（有 `chapter` 与引文时；没有则 `需人工定位`）。不做自动跳转猜测。

#### 15.3.3 组合结论与状态

| 状态 | 展示 |
| --- | --- |
| 未体检 | `还没体检` / `确定性体检不调模型，几秒出结果。` / `开始体检` |
| 体检中 | 按钮 `体检中…`；面板保留上次结果并降透明度 |
| 通过 | `体检通过` / `没有硬伤；3 条提醒可以不改。` |
| 有硬伤 | `2 条硬伤` + 列表；主按钮 `按技能改写` |
| AI 复检中 | `AI 复检中…`，预计 1–2 分钟；可关闭面板，完成后 Toast |
| AI 复检失败 | `语义复检失败：模型超时` / `确定性结果仍然可用。` / `重试` |
| 正文已变化 | 旧结果标 `结果基于旧稿`，按钮 `重新体检` |
| 无正文 | `这一章还没有正文` / `先写再体检。` / `去开写` |

### 15.4 按技能改写

#### 入口与按钮

- 每章行内 `按技能改写`（有硬伤时变 primary）。
- `ChapterCheckPanel` 顶部主按钮 `按技能改写`，自动带入体检问题。
- 细纲页 `ReferencePanel > 体检` 同一按钮。
- 命令面板 `按技能改写第 N 章`。

#### 改写弹窗

```
┌ 按技能改写第 14 章 ────────────────────────────────── ✕ ┐
│ 只改命中问题的段落；保留已经发生的情节事实、人物关系和    │
│ 信息揭示顺序；不新增设定、不新增角色。改完停在待确认。    │
│ ┌ 这次用哪些技能 ────────────────────────────────────┐ │
│ │ ☑ 去 AI 味（4 处解释情绪、2 处章末总结句）          │ │
│ │ ☑ 对话打磨（2 条口吻问题）                          │ │
│ │ ☐ 场景落地                                          │ │
│ │ ☑ 连续性检查（1 条吃书）                            │ │
│ │ ☑ 章末钩子（章尾偏弱）                              │ │
│ │ ☑ 文风样本（有 2 段样章）                           │ │
│ │ 平台打法：始终开启（平台禁忌不能关）                │ │
│ └─────────────────────────────────────────────────────┘ │
│ 补充要求（可选）  ┌───────────────────────────────────┐ │
│                   │ 例：只改第 3、7 段，不要动结尾。   │ │
│                   └───────────────────────────────────┘ │
│ 旧稿会进「废章」，可恢复。生成约 1–3 分钟。              │
│ [取消]                                      [开始改写]   │
└───────────────────────────────────────────────────────────┘
```

#### 预选规则

| 体检结果 | 默认勾选 |
| --- | --- |
| 有 AI 痕迹硬伤或判定「差」 | 去 AI 味 |
| 有口吻/对话问题 | 对话打磨 |
| 有节奏/场景概括问题 | 场景落地 |
| 章尾钩子弱 | 章末钩子 |
| 有吃书/连续性/关系/伏笔问题 | 连续性检查 |
| 有样章且文风漂移 | 文风样本 |
| 没有任何问题 | 去 AI 味 + 连续性检查（保守组合） |

平台打法始终开启且不可取消；虐文公式跟随书，不在改写弹窗单独开关（避免和书级模式打架）。

#### 硬约束（必须写进提示词与验收）

1. 保留所有已经发生的情节事实、人物关系和信息揭示顺序。
2. 不新增设定、不新增角色、不新增能力；不改变伏笔的埋/收章。
3. 只改命中问题的段落，不整章推倒重来；不改变章末钩子的类型。
4. 改完 `approved: false`，停在待确认；旧稿写进 `drafts/`，可在废章恢复。
5. 改写后自动重跑确定性体检；若正文 <300 字、撞硬规则或字数低于目标 75%，视为失败，保留旧稿。
6. 改写最多 1 次；失败不自动重试，交作者决定。

#### 运行与失败

- 按钮 `正在按技能改写…`；弹窗不可重复提交（`rewriteBusy` 单飞）。
- 成功：Toast `第 14 章已按 4 个技能改写，停在待确认`；面板刷新为新体检结果，并显示 `改写前 12 处 AI 痕迹 → 改写后 3 处`。
- 失败：`改写失败：模型超时` / `旧稿一个字没动。` / `重试`、`取消`；弹窗保持打开。
- 部分技能失败（例如去 AI 味改写后仍命中）：不报错，显示 `去 AI 味后仍有 3 处，建议人工看`。
- 单章重试：从改写弹窗直接重试；不改其他章。

#### 文案

| 位置 | 文案 |
| --- | --- |
| 按钮 | `按技能改写`、`按技能改写第 14 章`、`正在按技能改写…` |
| 说明 | `只改命中问题的段落；保留情节事实，不新增设定；改完停在待确认。` |
| 成功 | `第 14 章已改写，停在待确认。` |
| 失败 | `改写失败：{原因}` / `旧稿一个字没动。` |
| 空问题 | `这章没有明显问题` / `仍可按保守组合改一遍，或直接存档。` |
| 并发 | `第 14 章正在改写，等它结束。` |

### 15.6 数据契约（本节新增）

#### GET `/projects/writing-skills?dir=`

```json
{
  "skills": {
    "deai": true,
    "dialogue": true,
    "scene": true,
    "hook": true,
    "continuity": true,
    "platform": true,
    "nuewen": false,
    "styleSamples": true
  },
  "availability": {
    "nuewen": { "enabled": false, "reason": "这本书未开启虐文模式" },
    "styleSamples": { "enabled": true, "reason": "" }
  },
  "updatedAt": "2026-11-24T06:20:00.000Z"
}
```

#### PUT `/projects/writing-skills?dir=`

请求：`{ "skills": { "deai": true, "scene": false, … } }`
响应：`{ "ok": true, "skills": {…}, "updatedAt": "…" }`
- 只接受 8 个已知键的布尔值；未知键忽略并返回 `ignored`。
- 非虐文书传 `nuewen:true` → 400 `SKILL_UNAVAILABLE`，`message:"这本书未开启虐文模式"`。
- 保存只影响书默认，不影响当前正在运行的批次。

#### outline / prose 请求扩展

`POST /projects/chapters/{n}/outline` 与 `/prose` 请求增加：

```json
{
  "skillOverride": { "deai": false, "scene": true }
}
```

响应增加：

```json
{
  "skillsApplied": {
    "deai": true, "dialogue": true, "scene": true, "hook": true,
    "continuity": true, "platform": true, "nuewen": false, "styleSamples": true
  },
  "skillRuns": [
    {
      "skill": "deai",
      "stage": "post",
      "scanned": true,
      "hits": 12,
      "verdict": "差",
      "rewritten": true,
      "extraCalls": 1,
      "failed": false,
      "message": ""
    }
  ]
}
```

- `skillRuns` 只在真正执行/跳过的技能上出现。
- 去 AI 味改写失败不阻断本章落盘：`prose` 仍返回 `ok:true`，`skillRuns[deai].failed=true`，`chapter` 带 `writingFlags:["deai-failed"]`；界面在章行显示 `去 AI 味未完成`，可手动「按技能改写」。
- 去 AI 味最多改写 1 次；改写后重新扫描，不循环。

#### GET `/projects/chapters/{n}/check` 响应扩展

保留现有字段，新增：

```json
{
  "aiTells": {
    "verdict": "差",
    "density": 3.2,
    "total": 12,
    "categories": [
      {
        "id": "explain-emotion",
        "label": "解释情绪",
        "count": 4,
        "severity": "mid",
        "hint": "改成动作、停顿或具体细节",
        "samples": [
          { "text": "他很难过", "line": 9, "paragraph": 3, "offset": 52, "quote": "他很难过，却没有哭。" }
        ]
      }
    ]
  },
  "metrics": {
    "chars": 2380,
    "dialogueRatio": 0.31,
    "endHook": { "ok": false, "reason": "章尾偏弱" }
  }
}
```

`findings` 仍返回原有 `ai-tell-*`；前端以 `aiTells` 分组展示，避免重复列出。`paragraph` 1 起算，`offset` 从段首起算。

#### POST `/projects/chapters/{n}/ai-check` 响应扩展

新增 `semantic.groups`：

```json
{
  "semantic": {
    "groups": [
      {
        "id": "continuity",
        "label": "吃书",
        "findings": [
          { "severity": "high", "message": "与第 12 章矛盾：钥匙在阿枝手里", "hint": "改成本章沈默从阿枝处取回", "quote": "…" }
        ]
      }
    ]
  }
}
```

兼容：旧响应没有 `semantic` 时，前端按 `findings[].code` 映射到六组；未知 code 进 `其他`。

#### POST `/projects/chapters/{n}/rewrite` 请求扩展

```json
{
  "reason": "体检发现 2 条硬伤",
  "instruction": "只改第 3、7 段",
  "skills": ["deai", "dialogue", "continuity", "hook"],
  "model": null
}
```

响应：

```json
{
  "ok": true,
  "chapter": { "number": 14, "approved": false, "…": "" },
  "text": "……",
  "chars": 2380,
  "check": { "…新的确定性体检，含 aiTells…": "" },
  "skillsApplied": ["deai", "dialogue", "continuity", "hook"],
  "backupDraft": "drafts/014-夹层-rewrite-….md",
  "extraCalls": 1
}
```

- `skills` 为空时按当前章体检问题自动预选；平台打法始终加入。
- 400 `NO_TEXT`；404 `CHAPTER_NOT_FOUND`；409 `REWRITE_BUSY`；502 `LLM_ERROR` / `REWRITE_TOO_SHORT` / `REWRITE_VIOLATES_RULES`。
- 任何失败都不改动正文与索引。

### 15.8 边界情况（本节）

| 场景 | 表现 | 允许 | 不允许 |
| --- | --- | --- | --- |
| 非虐文书打开虐文技能 | 行禁用，`未开启虐文模式`，链接去细纲页 | 去开启 | 静默忽略并显示已开 |
| 关闭平台打法 | 警告条；生成仍可继续 | 继续写 | 承诺不会平台违规 |
| 无样章开文风样本 | 行可开但标 `不生效` | 去贴样章 | 显示「已生效」 |
| 去 AI 味改写失败 | 本章仍落盘，行标 `去 AI 味未完成` | 手动按技能改写 | 整章失败/回滚 |
| 去 AI 味后仍命中 | 显示剩余数量 | 人工改、忽略 | 无限自动重写 |
| 体检时正文为空 | `先写再体检` | 去开写 | 调模型 |
| AI 复检超时 | 确定性结果保留，语义区显示失败 | 重试 | 清空确定性结果 |
| 改写时正文被其他窗口改动 | 409 `REWRITE_CONFLICT` | 刷新后重试 | 覆盖新稿 |
| 改写后 <300 字 | 失败，旧稿保留 | 重试、换技能 | 落盘半成品 |
| 改写撞硬规则 | 失败，旧稿保留，列命中规则 | 调整后重试 | 静默落盘 |
| 改写新增设定 | 语义复检提示；确定性硬规则可能拦截 | 人工复核 | 声称「绝不新增」而不检查 |
| 重复点改写 | 按钮禁用；服务端 409 | 等待 | 并发两路模型 |
| 体检结果过期 | 标 `结果基于旧稿`，按钮 `重新体检` | 重跑 | 把旧结果当新稿 |
