# 文风裁决

## 用途

当多个来源对「怎么写」给出不同要求时，用固定优先级裁决，避免模型在冲突中随机选边。
裁决按维度取第一个明确、适用的要求，不把整份文件互相覆盖。
表达可以听作者的；事实、信息边界与结构协议不听文风的。

## 优先级

从高到低，逐维取值：

1. **当前请求**：本次任务里作者明确说出的要求。
2. **本书文风**：本书的设定文件里已写明的写法偏好。
3. **本书作者记忆**：本书范围内记录的 active 长期习惯。
4. **题材 / 全局**：题材包与全局 active 记忆。
5. **主对标**：对标作品可观察到的写法，置信度低时不压作者选择。
6. **默认值**：通用提示词与检测器的兜底规则。

未声明的维度才向下补齐；高层级没有表态，不等于高层级否定了低层级。

## 硬规则

1. **按维取值**：句长、视角、人称、标点、对话落法、情绪直写、修辞、叙述者评论、收尾方式分别裁决。不要因为一条要求不同，整份覆盖其他维度。
2. **事实与表达分开**：文风只能改变「怎么写」。细纲事件、人物关系、已发生事实、信息揭露边界、字数范围、文件结构、追踪协议不因文风改变。
3. **不借文风改事实**：有限全知可以切换视角，但不等于可以提前揭底；转限知时宁可暂不叙述角色无从得知的信息，也不补「他早已知道」「后来发现」来保全原文。
4. **冲突只问一句**：按优先级已能解决的，不询问；确实无法判定且会影响成稿时，只问一句「这条按当前请求，还是按本书文风？」不列问卷。
5. **默认规则不高于作者选择**：检测器、通用提示词里的「必须」「禁用」是默认写法，作者明确选择且有功能时可以登记放行。
6. **放行要留痕**：需要豁免时，登记获准的字面片段，并写明来源与用途；不为让脚本闭嘴而自动放行，也不把一次性的要求写成长期习惯。
7. **一次性要求不写回长期记忆**：本轮临时指定的写法只在本次生效，不推断为本书习惯。
8. **对标不压本书**：对标作品的低置信观察，不能推翻本书文风与作者明确选择。
9. **审稿照常看缺陷**：不能因为写法是作者选的，就跳过因果、可读性与情绪效果的实际缺陷；也不能仅仅因为用了默认写法就判错。
10. **裁决要可传递**：把生效要求、来源、被覆盖的默认条款、必须保留的事实边界写清楚，交给后续写作、改写与审稿使用。

## 检查清单

- [ ] 当前请求是否明确，是否只影响指定范围？
- [ ] 本书文风文件是否完整读取，而不是只看摘要？
- [ ] 是否存在本书作者记忆，是否只取 active 条目？
- [ ] 题材或全局默认是否适用于本书？
- [ ] 对标观察是否低置信，是否被误当成硬规则？
- [ ] 冲突能否拆到具体维度分别裁决？
- [ ] 表达裁决是否被误用来改变事实或信息边界？
- [ ] 放行项是否登记了来源与用途？
- [ ] 一次性要求是否被误写回长期记忆？
- [ ] 无冲突时是否写了「按本书文风」，而不是制造不必要的询问？

## 反模式

- 用「本书文风」整份覆盖当前请求，或反过来用当前请求推翻所有本书设定。
- 把对标作品的句子级特征当成必须复刻的规则。
- 用文风裁决改变细纲事件、人物关系、信息揭露顺序。
- 因作者偏好某写法，就忽略它造成的阅读障碍或事实矛盾。
- 检测器一报警就放行，不判断是否真的有功能。
- 把临时要求写成长期作者记忆。
- 遇到冲突不裁决，反复询问作者，拖住写作。
- 裁决只写「按作者喜好」，不写具体生效维度与来源。

## 输出约束

- 输出一份 `style_resolution`：本次生效的表达要求、各自来源、被覆盖的默认条款、必须保留的事实与信息边界。
- 无冲突时只写「按本书文风」，不罗列全部默认值。
- 只列与本次任务有关的冲突，不写完整文风画像。
- 无法按优先级裁决时，只提一个具体问题，并给出默认建议。
- 裁决本身不进入小说正文，只作为写作说明传递。
