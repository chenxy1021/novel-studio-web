# 单章质检

## 用途

用固定顺序检查一章是否可交付。每一步都要给出可执行判定，不写「感觉不错」。
质检只判断与指出问题，不替作者补写剧情；字数不足不靠注水解决。
发现问题后按严重度处理：硬伤先修，建议项排期，提示项记录。

## 硬规则

按十三步依次执行，不跳步、不合并：

1. **细纲九字段**：单元 ID、位置、核心事件、内容概括、情节安排、情节点、涉及人物、结尾设定、字数范围。缺字段先补建或标「待补充」，不带着空细纲开写。
2. **上下文读取**：读续写状态卡七栏、本章需要的设定条目、在场角色卡。确认本章时间、地点、人物已知信息没有断档。
3. **意图与契约风险**：用一句话写清本章意图，例如「账单暴露 → 逼问 → 反证 → 公开代价」。核对细纲是否标了需补强或契约风险，把补强办法写进本章意图。
4. **标题预检**：标题是否与核心事件一致，是否和已有章节重名或高度重复。重名就改名并同步正文文件名。
5. **写作分组**：长篇分前组、后组写；前组写完测字数，后组按剩余区间收口。一次成文时也要在交付前核对总字数。
6. **情节点落点**：细纲每个情节点至少出现一次，漏写就退回补写批准内容，不以字数为由跳过。
7. **机械检测**：跑 AI 句式、模型退化、照搬细纲、字数四项检测。阻断项清零，提示项逐条读原文判断。
8. **钩子与爽点**：章尾有往下看的理由；高压或推进章爽点到位，低压章有阶段目标；爽点前有可指认的铺垫。
9. **契约四问**：主角是否靠自己的选择挣到本章结果？收益是否被配角、机构或巧合无交换地拿走？有没有提前动用后面的底牌？旧期待有没有付利息、有没有留下新期待？
10. **元信息扫描**：标题行以外清除「第 X 章、上一章、本章、前文、后文、伏笔、细纲、读者」一类工程词，改成角色能感知的事件锚点或相对时间。
11. **检测结果处理**：S1/S2 必须修，S3 建议修，S4 仅提示。阻断项就地改净；提示项不机械归零，读数后判断是否真有问题。
12. **追踪更新**：提交本章变化、角色快照、伏笔推进、退役登记、下一章承诺。只登记真实发生的变化，不预填未来。
13. **提交后核对**：确认状态已提交、正文已保存、下一章承接明确。有需作者拍板的新增物，暂停提交并单独提问。

## 检查清单

- [ ] 细纲九字段齐全，没有用「待补充」蒙混过关。
- [ ] 状态卡七栏已读，本章没有与已知事实冲突。
- [ ] 本章意图一句话能说清，且与细纲一致。
- [ ] 标题与核心事件一致，没有重名。
- [ ] 每个情节点至少出现一次。
- [ ] 阻断级检测已清零，提示项已逐条复核。
- [ ] 章尾有具体钩子，不是总结或升华。
- [ ] 契约四问全部有明确答案，没有回避。
- [ ] 正文没有工程词泄漏，时间锚点可被角色感知。
- [ ] 字数在目标区间内；不足不注水，超出做一次净删。
- [ ] 本章变化已登记，退役项已显式处理。
- [ ] 新增人物、设定、关系、承诺已申报或已登记。
- [ ] 下一章承接点明确，承诺可验证。

## 反模式

- 为凑字数补环境描写、重复情绪、无意义动作或流程细节。
- 情节点漏写，用一句概括带过，然后继续往下写。
- 把「有钩子」当成免检通道，忽略本章推进不足。
- 提示项全部机械改掉，改完反而出现电报体或新模板。
- 契约四问只答「没问题」，不指出具体证据。
- 章节标题与正文核心事件脱节，或与旧章撞名。
- 提交时只更新正文，不更新追踪，留下跨章隐患。
- 发现新增物后自行决定保留，不向作者申报。
- 把计划当成已发生事实写进状态卡。

## 输出约束

- 输出逐项判定：通过 / 需修 / 待作者决定，每项附证据位置与一句理由。
- 需修项按 S1/S2 优先排序；S3/S4 单列，不阻塞交付。
- 不自行补写剧情凑字数；字数不足时给选项，由作者决定。
- 需要新设定或人物时单独列出，等确认后再写入正文与状态。
- 质检结论不写分数、百分比或「上乘/合格」一类无依据的市场判断。
- 最终附一句：本章读完后世界发生了什么变化，下一章要接住什么。
