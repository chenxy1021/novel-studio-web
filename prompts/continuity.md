# 续写状态卡

## 用途

用一张固定七栏的状态卡守住跨章一致性。写作前必须通读，写作后只更新变化项。
它服务下一章的热上下文，不是全书资料库；容量有限，写要点，不堆细节。
事实与计划分开：已经发生的写进状态卡，计划揭示的留在大纲。

## 固定七栏

1. **当前位置**：卷名、本章故事时间、场景地点。
2. **长期约束**：本书必须一直成立的规则、叙事承诺与底线，最多 6 条。规则按可违反程度标类别：
   铁律（破不了，只能绕）/ 契约（能破，但当场付明确代价）/ 惯例（能破，代价是社会性的）/ 谣言（人物以为成立，其实不成立）。
3. **核心角色状态**：最多 6 人，每人写身份/重要程度、当前位置（标「截至第 N 章」）、人物轨迹、目标、当前状态、
   能力资源、关系、已知信息、未结线。人物有外号 / 小名 / 化名时一并写进别名，正文用哪种称呼都算同一个人。
   位置和状态要带章号；人物换地点必须在正文里交代时间与路程，不能凭空切换。
   关键物品另记「在谁手里 / 什么状态 / 截至第几章」，转手要写清谁在什么时候因为什么交出去。
4. **活跃伏笔**：已埋设、仍需推进或回收的线，按重要度选取最多 8 条，写埋设章与计划回收方向。
5. **近三章速记**：只保留最近 3 章，每章一句「发生了什么 + 留下什么」。
6. **下一章承诺**：已经向读者或角色许下、下一章应接住的具体事项。
7. **连贯性风险**：容易被误当已知事实的信息、未解释的承诺、时间线或伤势可能冲突的点。

## 硬规则

1. **写作前必读七栏**：先读完整状态卡，再取本章在场角色、要碰/要避的伏笔、必须履行的承诺与相关长期约束，写成写作速记。
2. **写作后只改变化项**：没有变化的栏保持原样，不整份重写；变化项明确标新增、修改或退役。
3. **容量纪律**：核心角色最多 6 人，活跃伏笔最多 8 条，近章只留 3 章。要进新条目时先合并语义重叠项或请作者取舍。
4. **长期约束不自动删**：新增第 7 条前先合并或让作者选；退役条目不靠省略表示，必须显式登记。
5. **计划不当事实**：未来第几章揭示、后续反转、尚未发生的承诺，写在大纲或「下一章承诺」，不写进已发生事实。
6. **角色已知边界**：角色状态里的「已知信息」只写他亲历、被告知或可合理推断的内容。读者知道不等于角色知道。
7. **伏笔状态可追踪**：每条伏笔写清埋设章、当前状态（已埋 / 推进中 / 部分揭示 / 已回收）、计划回收方向。不把未揭示的章号填成既成事实。
8. **近章速记写变化**：每章一句讲清状态变化与遗留问题，不写剧情复述。
9. **承诺要具体**：下一章承诺写成可验证的动作或事件，不写「继续推进感情」这类空话。
10. **风险栏只写风险**：写可能被误用的信息与冲突点，不写已经解决的旧问题。
11. **单一权威**：角色状态、伏笔、时间线以结构化状态为准，派生视图不手改；发现不一致时回到权威状态修正。
12. **回忆与当下分开**：允许写回忆 / 倒叙，但要用当下的人、动作或物件做入口，并交代何时回到现在。
    回忆里的时间、地点、人物状态按当时写，不记成当前状态；章记忆用 `isFlashback` 标整章基调，
    单条时间线事件用 `flashback` 标「发生在过去」。

## 检查清单

- [ ] 七栏齐全，顺序固定，没有自创栏目。
- [ ] 当前位置的时间与地点和上一章结尾接得上。
- [ ] 长期约束没有超过 6 条，退役项已登记；每条规则都有类别（铁律/契约/惯例/谣言）。
- [ ] 核心角色没有超过 6 人，每人状态与本章正文一致；正文用了别名也能对上同一个人。
- [ ] 活跃伏笔没有超过 8 条，本章碰到的线有推进或明确不动。
- [ ] 近三章速记没有超过 3 章，每章一句话有变化、有遗留。
- [ ] 下一章承诺具体可验证，没有空泛表述。
- [ ] 连贯性风险写的是可能冲突点，不是已解决事项。
- [ ] 角色知道什么、不知道什么没有越界（信息差按「谁知道 / 谁不知道 / 谁以为知道」写）。
- [ ] 人物位置和物品持有人与上一章接得上，或正文已交代移动与转手过程。
- [ ] 回忆 / 倒叙有清楚的入口和回到现在的时点，回忆里的状态没有被记成当下状态。
- [ ] 状态卡里没有把计划写成已发生事实。
- [ ] 本章新增角色、设定、关系、承诺已经登记或单独申报。

## 反模式

- 只记结果不记变化：写「主角赢了」，不写他付出了什么、谁的态度变了。
- 把大纲计划抄进状态卡，当成读者已知事实。
- 手改派生视图，导致状态与视图不一致。
- 退役靠省略：旧约束、旧角色、旧伏笔直接消失，没有登记。
- 热上下文塞满：核心角色十余人、伏笔二十条，写作时反而抓不住重点。
- 承诺写成愿望：「下一章继续升温」无法验证是否兑现。
- 状态卡里写剧情细节，挤掉真正需要跨章记住的约束与风险。
- 角色状态写作者知道的信息，不区分角色本人知道什么。

## 输出约束

- 输出更新后的状态卡或增量 delta；变化项标明新增、修改或退役，未变项明确写「不变」。
- 不写入正文尚未发生的内容；计划与承诺放在对应栏目，不混入事实。
- 与已有事实冲突时先指出冲突点，等裁定后再改；不静默改写历史。
- 只写要点，不复制正文段落；容量超限时先合并或请作者取舍。
- 交付时附一句「本章触碰了哪些伏笔 / 兑现了哪些承诺 / 留下哪些风险」。
