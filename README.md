# Novel Studio · 网页版

小说创作工作台，从 DSH 插件 `novel-studio` 独立出来：Vue 3 + Vite 前端，FastAPI 后端。
正文与章节索引仍是磁盘文件；每本书的设定、细纲、伏笔、记忆等可变数据存在全局 SQLite，
`project.json` / `bible.json` 作为兼容快照，方便旧工具和人工查看。

## 起服务

前后端一个脚本管完（缺依赖会先装）：

```bash
./scripts/dev.sh            # 起 API + Web，Ctrl-C 一起停
./scripts/dev.sh open       # 起完顺便打开浏览器
./scripts/dev.sh status     # 看端口、健康检查、日志位置
./scripts/dev.sh stop       # 停掉两个服务（按端口收，孤儿进程也能收）
./scripts/dev.sh restart    # 先停再起
```

`make dev` / `make stop` / `make status` 是同一套的快捷方式。

- Web：http://127.0.0.1:5180
- API：http://127.0.0.1:8010/api/ping
- 端口写死：8010 / 5180（8000 / 5173 给别的项目用）。Vite 把 `/api` 代理到 8010。
- 日志和 pid 在 `.run/`（已 gitignore）：`api.log` / `web.log`。

只跑一边：

```bash
make api     # 后端
make web     # 前端
make test    # backend pytest + 前端 store 自测（make test-store 只跑前端）
```

## 存储模型

| 数据 | 位置 | 说明 |
|---|---|---|
| 每本书的设置、人物、世界观、势力/地点/物品/规则、文风 | 全局 SQLite | 默认 `~/.dsh/novel-studio/studio.db`，`DSH_NOVEL_DB` 可覆盖；`books.dir` 是稳定键 |
| 卷、细纲、段落纲、伏笔、章/卷记忆、人物状态、关系、时间线 | 全局 SQLite | 读写仍走原来的 `store` 接口，业务层无感 |
| 正文 | `chapters/NNN-标题.md` | 唯一真相，保留原格式 |
| 章节索引 | `chapters/index.json` | 标题、摘要、字数、审阅状态 |
| 提示词模块 | `prompts/*.md` | 固定内容不进数据库；书目录下同名文件可覆盖 |
| 平台规则、模板、写作技能清单 | 代码/仓库 | 版本化，随代码走 |
| 兼容快照 | `project.json` / `bible.json` | 每次保存同步写完，可随时从数据库重建 |

旧书首次读取会自动导入数据库；已有 `ledger/*.jsonl` 在第一次读时导入 `ledger` 表，
文件保留作审计与导出。删除整本书时，目录和数据库行一起删，避免同路径重建时复活旧数据。

## 页面

侧栏按一天的用法分组，不按功能平铺：

| 组 | 页面 |
|---|---|
| 工作台 | **今日**：一屏回答「现在做什么」——待确认章、到期伏笔、低于下限的章；**开书**：选题之后按「大纲+世界观 → 设定 → 伏笔 → 细纲+正文」推进；**文风**：全书默认写法 + 8 位作家的写法参照 |
| 写作 | 进度（逐章审阅 / 体检 / 按技能改写 / 选择存档）、废章 |
| 规划 | 大纲（结构大纲 / 世界观 / 地图三栏；Markdown 阅读、世界观小节导航、由设定生成 SVG 的地点地图，无图时回退结构图）、细纲（按段的段落纲 + 本章参考资料）、伏笔 |
| 资料 | 人物（人物卡 / 性格动机 / 位置轨迹 / 人物关系矩阵与关系图）、记忆（时间线 + 叙事记忆 + 关键词回查）、设定（规则 / 世界纵深 / 势力 / 地点 / 物品 / 信息差 / 悬而未决） |
| 系统 | 设置（外观、自动存档、模型、修复、用量） |

### 写作动作

- 今日页或进度页点「写作」打开开书面板：**选章 → 确认本批文风 → 选写作技能 → 看参考资料 → 逐章生成**。
- **没有伏笔不能写正文**：至少有一条伏笔才允许开写，前端按钮和后端 `NO_FORESHADOW` 都会拦住；正文要按伏笔网推进，空着写会一路丢线。
- 今日页的「下一批」与细纲 / 写作面板同源：已经排过段落纲时直接写到这一段末尾，段落纲没覆盖到下一章才按每段章数往后推。
- 每章先出细纲再写正文；失败的章停下，可单章重试、跳过并继续或本章完成后暂停。
- 生成过程实时可见：大纲+世界观、设定（人物/规则/物品/地点/世界纵深）、伏笔、细纲、正文、按技能改写的模型输出
  都边写边滚，带当前阶段和字数；设定分四批拆，流里会标出每批的小标题。
- 正文落盘后自动回写「记忆」（故事内时间、出场人物、事件、时间线、人物状态变化），不用手动生成。
- 人物状态分三层：**出场状态**（`appearanceStatus`）、**当前状态**（`status` + `statusLog` 按章轨迹）、
  **最终状态**（`finalStatus`，补进设定按大纲结局补，结局没写清就留空）。出场活着、第 40 章死了这种变化，
  由章记忆里的 `characterStates` 在本批存档回写时并进 bible（只在正文写明死亡/失踪/退场或死而复现时才记，
  模型推测不算），`status` 跟着推到「死亡」、`exitChapter` 记 40，退稿会把这一章的死亡一起撤回。
  人物页显示当前状态、结局状态和状态轨迹；提示词里渲染成「状态:在场→死亡（第40章起）」，
  AI 复检还会对照这张表问一句「已离场的人有没有无故回来」。
- 写完整批停在「待确认」，不会自动存档；存档与退回都支持勾选多章批量处理。
- 一批写完后可直接「补进设定」：只看最近 8 章正文，已有条目（含别名）一律跳过，不会覆盖旧设定。
- 大纲和世界观默认按 Markdown 阅读，可切回原文；分卷按矛盾阶段切，卷长不固定。
- 进度页与细纲页可对单章做确定性体检、AI 语义复检、按技能改写；旧稿进「废章」可恢复。
- 伏笔页顶部四个格子就是筛选：未收 / 超期（未收里回收章已经到的）/ 已收 / 放弃，再和层级筛选取交集；
  格子上的数字按当前层级数，点进去看到的就是这个数。

### 键盘与查找

- `⌘K` / `Ctrl K`：命令面板。页面、章节、人物、伏笔和动作一起搜；`↑↓` 选择，`↵` 执行。
- `/` 直接打开命令面板；`?` 看全部快捷键；`T` 切主题；`W` 打开写作面板；`G` 后按 `H/P/X/O/D/F/M/W/C/S/,` 跳页面。
- 进度页：`J/K` 走章，`↵` 存档或展开，`R` 退回，`B` 按批体检。
- 从今日页/命令面板点某一章会带 `?chapter=N` 进进度页——这时**不会**自动存档，留给作者确认。

### 外观

主题三态（跟随系统 / 浅色 / 深色）存在 `localStorage` 的 `ns.theme`，token 用 `light-dark()` 一次定义两套色，不靠 JS 重算。侧栏可收成图标栏（`ns.rail`）。

## 开书流水线

选定选题（书名 + 简介 + 章数 + 每章字数）之后，按旧插件的顺序推进，不跳步：

| 步骤 | 入口 | 产物 |
|---|---|---|
| 1. 大纲 + 世界观 | `POST /api/projects/blueprint` | `project.outlineText` / `project.worldText` + 卷表；虐文自动带入「最 X → 最非 X」公式 |
| 2. 人物 · 规则 · 物品 · 地点 · 世界纵深 | `POST /api/projects/settings` | 人物（含别名）、关系、信息差、势力、地点、物品、规则、力量体系、社会常识、大事记、术语、文风；只补不覆盖 |
| 2b. 写后补设定 | `POST /api/projects/settings/supplement` | 从最近正文抽新出现的人物/地点/物品/势力/规则；同名跳过 |
| 3. 伏笔 · 草蛇灰线 | `POST /api/projects/foreshadow/generate` | 核心 / 卷级 / 情节三层，回收章晚于埋设章；同名或同层级、埋收章几乎重合的线视为重复，不重复入库 |
| 4. 段落纲 | `POST /api/projects/segments` | 默认 10 章一段（设置页可改 3–30）的台阶：目标、转折、节奏、现场、出场人物 |
| 5. 细纲 + 正文 | `POST /api/projects/chapters/{n}/outline` → `/prose` | 细纲存 `outlines`，正文写 `chapters/NNN-标题.md`，状态待确认 |

`POST /chapters/{n}/generate` 保留为兼容包装（内部依次调用 outline + prose）；新界面走拆分接口，
这样可以先看细纲再决定写不写正文。写作运行有 `runId` 并发保护，同一章不会两个窗口同时写。

### 文风

- 「文风」页在工作台组里维护书级默认；开书面板里选预设或改字段只作用于本批，不会悄悄改书默认。
- 开写前必须确认本批文风；改过字段会作废上一次确认。
- 优先级：**本批 override > 本书默认 > 平台默认**。
- 8 个作者预设：爱潜水的乌贼、辰东、恩养、刘慈欣、三九音域（正文写法）+ 猫腻、烽火戏诸侯、余华（叙事与人物参照）。
- 预设只注入「写法特征」，不复制原文；本书字段与样章优先。文风不改变细纲事件和已发生事实。

### 写作技能

开书面板可开关：去 AI 味、对话打磨、场景落地、章末钩子、连续性检查、平台打法、虐文公式、文风样本。
技能决定细纲/正文提示词注入哪些方法模块（`prompts/`），也决定改写弹窗的默认勾选。

### 参考资料包

细纲与正文生成前会打包实际注入的资料：本卷大纲、本章台阶、伏笔、人物卡（含别名）/当前状态/关系、
规则、世界观、势力、地点、物品、力量体系、社会常识、大事记、术语、人物位置与物品去向、信息差、
近章记忆、已存档摘要、卷摘要、时间线、上一章结尾、文风、平台打法。
`GET /api/projects/chapters/{n}/references` 返回与提示词一致的条目数和缺失项，供「本章资料」面板展示。

每段有字数预算。超预算时不再从段尾硬切半句话，而是先把清单按「本章相关度」排序——台阶 / 细纲 /
上一章结尾 / 强调里点到的名字优先，最近出场过的其次，已离场的排最后——再整条装进预算；装不下的
条目折成一行名录（`其余 N 条未展开：姓名（状态）…`）。所以人物卡显示 `8/18 条` 时，剩下 10 个人
的名字和状态仍在提示词里，不会被模型当成不存在。其他未收伏笔按「计划收的章」由近到远排。

写正文前还会先做一次**实体解析**（`resolve_chapter_entities`）：从本章细纲、段落纲台阶、上一章
记忆、前两章出场人物、作者强调里点出这一章会用到的人/地点/物品/势力/术语/伏笔，每条带命中来源
（`台阶` / `细纲` / `第54章` / `常驻`）。解析到的给完整卡，没解析到的只留名字和状态；面板「本章
认定相关」一栏可以逐条看来源。回测第 1–55 章：细纲 + 台阶 + 上一章记忆 + 近两章出场，人物覆盖
100%（第 10 章以后），平均多带 3 人；把全部人物塞进去的平均多带是 14.2 人。地点不做解析——真值
里的细地名（「登记室正门台阶」）不在 bible 的 20 条粗地名里，解析不出来就整表保留、名录兜底。

### 设定与连续性

设定不是简介，是写正文时要对照的事实。四类资料都有「截至第几章」的概念：

- **规则**按可违反程度分四类，写进 `enforce`：
  - `铁律`：破不了，人物或世界会因此不成立，只能绕；
  - `契约`：能破，但必须当场付代价（反噬、折寿、失忆、违约反扑）；
  - `惯例`：能破，代价是社会性的（被逐出、失信、得罪势力）；
  - `谣言`：人物以为是规则，其实不成立，打破时要揭示真相。
  每条规则另有 `cost`（违反代价）、`boundary`（什么时候不适用 / 漏洞）、`enforcer`（谁在执行）。
- **人物**：性别、年龄、种族、性格、外形、重要程度（核心/主要/次要/龙套）、角色层级（主角/配角/龙套）、
  首次出场章、退场章、出场状态（在场/失踪/死亡/已退场）、当前所在地（`location` + `locationAt` 章号）、
  人物轨迹（`locationHistory`）、想要/害怕/底线/弱点/秘密/说话方式、本事及限制与代价、
  当前目标，以及「他知道 / 他不知道 / 他误以为」。
  别名（外号、小名、化名、职务称呼）单独存在 `aliases`：生成设定时强制补全，正文、对白、段落纲和体检都按别名认同一个人。
- **世界纵深**：`powerSystem` 写力量 / 能力体系（总名、等级台阶、晋升、代价、上限、平衡），
  `society` 写政治/经济/货币/律法/禁忌/风俗/宗教/语言/技术，`history` 只收影响当下格局的大事，
  `glossary` 统一专有名词的叫法与用法。它们和规则一起进正文参考资料包，设定页「世界纵深」一栏可查。
- **物品**：持有人（`holder` + `holderAt` 章号）、状态（`state` + `stateAt`）、所在、转手记录（`transferLog`）、谁知道。
- **关系 / 信息差**：`relations` 是关系底稿（甲↔乙、当前状态、备注）；`infoGaps` 写每个秘密「谁知道 / 谁不知道 / 谁以为自己知道」。
  人物页顶部切「人物关系」：默认按 Excel 式矩阵看，行、列都是人物，序号在两侧，单元格是两人当前关系；备注多时可切明细列表。
  「关系图」一栏由 AI 读人物卡 + 关系底稿画一张独立 SVG（存书目录 `relation_map.json`），关系变了点「重新生成」；
  不写死排版，换一本书照样能画。图只经 `<img>` 渲染，脚本不会执行。
- **势力与地点的状态**：两者都有 `state` + `stateAt`（截至第几章），势力另有 `attitude`（对主角的当前态度），
  地点另有 `occupied`（现在被谁占着）。状态随剧情变化，不能只写静态介绍；写后回写也会更新它们。
- **地点与地图**：地图不写死排版。点「AI 画地图」时，后端用 `bible` 里的**世界观正文 + 世界设定 + 社会常识 +
  力量体系 + 大事记 + 地点 + 势力**拼提示词，让模型画一张独立 SVG，存进书目录的 `map.json`；
  改了设定或补了方位后点「重画地图」重新生成。SVG 只经 `<img>` 渲染（脚本不执行），并会先剥掉
  `<script>` / `oni*` 之类的东西。还没画过时显示按地点字段自动排的结构图，保证随开随看。

  地点字段决定结构图怎么排，两种写法都支持：
  - 平面地理（大陆、国家、城市、山川、海路）：填 `mapX` / `mapY`（0–100，西→东、北→南），有坐标的地点直接落点，
    同一 `mapScope` 的地点用虚线圈成一区；
  - 层层相套（内外城、内门外门、舱段、楼层）：填 `mapLayer`，从里到外写「序号 层名」（如 `1 内城`），地图按层套圈。

  `mapScope`（所在范围）、`mapBearing`（八方位）可显式给；没写时从 `geo` / `structure` 里的地点名和方位词推断，
  还推不出就同层均分。被两处以上地点提到的地名算「范围」，不画成点。`terrain` 是自由文本（城/镇/村/山林/岛/塔…），
  只取首字当节点字形。图里不画海岸与山脉，也不替作者编地形。
  AI 图与结构图共用左侧地点索引：按层或范围分组、可搜索，点地点看注释。

连续性靠正文回写，不靠手抄：每章记忆落盘时抽出 `moves`（谁去了哪、怎么去的）和 `items`（谁拿了什么），
但要等**按批体检的这一批全部存档**后才由 `continuity.apply_continuity` 并进设定——没存档的章改了也不脏设定；
同章同地点/同持有人不重复记账，历史保留最近 40 条。
参考资料包会注入「位置与物品去向（截至上一章）」和「信息差」，并明确提醒：人物可以跨章移动，
但正文必须交代时间与路程，不能凭空切换。

### 记忆

记忆不是手写台账，是正文的派生数据：**每章落盘后自动回写**（`memory_gen.auto_write_back`），
写到某卷最后一章时顺带更新卷摘要；改写落盘后也会重算该章记忆。回写失败不影响正文，
只会在记忆页留下一个「待补」缺口。

- 章记忆：故事内时间、地点、出场人物、关键事件、谁知道什么、关系变化；回忆 / 倒叙为主的章带 `isFlashback`。
- 卷摘要：主线、支线、关系、读者已知、带出下一卷、与大纲偏差。
- 时间线：按章投影，**只在记忆页维护**（设定页不再放第二份，避免两处对不上）。单条事件可带 `flashback`，
  表示它发生在过去而不是本章的当下；时间线里会标「回忆」，参考资料包也会带上这个标记。
- 记忆页只读：按卷/人物/地点筛选、关键词回查；旧稿或失败留下的缺口可单章补写或批量补齐。
- 回写默认开启；`DSH_NOVEL_AUTO_MEMORY=0` 可关掉（测试与离线环境用）。

### 体检与改写

- 确定性体检不调模型：字数、平台格式、AI 痕迹（分类 + 次数 + 引文 + 段号/段内偏移）、章尾钩子、规则。
  它不判断故事内时间的先后，所以正文写回忆 / 倒叙不会被体检误报成时间线错误；回忆只在记忆里用 `isFlashback` 标注。
- AI 语义复检不再开放式「找问题」，只对照一张固定清单逐项判定：细纲必须项/回避项、本章应埋/应收的伏笔、
  本章出现过的物品/地点/势力对设定、世界硬规则、截至上一章的人物状态、与上一章结尾的衔接、章内一致、限知视角。
  每项默认通过，判不过必须逐字引用正文原句（细纲缺失、伏笔没写这类「缺席」项除外）。
  清单全过就是通过；清单外最多记 2 条动机/信息重复建议，不影响结论。伏笔项记为「建议」而不是硬伤，不逼整章重写。
- 按批体检会多跑一次模型核对到期伏笔：正文里已经写了、又能引得出原句的，自动追加一条「已收」记进账本，
  提醒和伏笔页都不再显示；AI 复检已确认过的收线项同理。判错了在伏笔页点「重新打开」就能改回未收
  （账本只追加一条 reopen，原事件都留着）。核对调用失败不影响体检本身，提醒照常显示。
- 复检按轮走：第一次点开一轮，之后「刷新本轮」只把改掉的条目摘掉，不再问模型；原句在正文里消失的条目
  自动算已解决。整章改写、退稿或点「新一轮复检」才按同一张清单重判。
- 体检缓存跟着正文走：正文改过就按当前稿重跑，改掉的问题自动取消，不会拿旧稿的结论继续挂着。
- 确定性体检也会误判：命中句旁边点「忽略」即可记下误报，重跑不再计入，也不再挡存档。
- 按技能改写只改命中问题的段落，保留已发生事实、人物关系与揭示顺序；新稿回待确认，旧稿进废章。
- 改写要求里一定带着本轮 AI 复检没过的条目：页面刷新过、前端手里没有复检结果时，后端从账本里补；
  打开改写弹窗会自动把进行中的复检轮次捞回来（`GET /chapters/{n}/ai-check/current`，不调模型），
  所以在弹窗里取消勾选的条目会作为 `dismissed` 传上去，不会再被补充逻辑塞回提示词。
- 改写要守住字数硬下限（设置页的「每章字数硬下限」，长篇默认 1800）：提示词里写明现在多少字、
  还差多少，模型交稿不够就先补写一次，仍不够则判失败、旧稿一个字不动。
- 段落改写同样不许把一章改薄：本章已经不到下限时，这一段不能比原来短。
- 改写后自动重跑确定性体检；正文过短、低于字数底线或撞规则时判失败，旧稿一个字不动。

## 生成模型

写作走 OpenAI 兼容接口，配置存在 `~/.dsh/novel-studio/gateway.json`（用户级，不写进书稿目录）。
设置页可直接改 Base URL / 正文模型 / 轻活模型，「测试连接」会请求 `{baseUrl}/models` 并列出可用模型。
「写作与存档」里的每章字数下限、每段章数也可以改，保存后写回 `project.json`（`PUT /api/projects/book`）。

长文本生成另有流式版本（`/api/projects/blueprint/stream`、`/settings/stream`、
`/settings/supplement/stream`、`/foreshadow/generate/stream`、
`/chapters/{n}/outline|prose/stream`、`/chapters/{n}/rewrite/stream`），走 SSE：
`stage` 报阶段、`delta` 推增量正文、`done` 带与同步接口完全一致的最终结果、`error` 统一错误。
设定拆四批（人物 / 势力与地点 / 物品与规则 / 世界纵深），每批切换时流里也会标出小标题；
模型回了不可解析的 JSON 会换一次请求重试，不再整轮直接判失败。同步接口保留，脚本和旧调用不受影响。

| 接口 | 作用 |
|---|---|
| `GET /api/settings` | 读当前配置（不含 apiKey 明文） |
| `PUT /api/settings` | 写配置，`baseUrl` 必须是 `http(s)://` |
| `POST /api/settings/probe` | 拿页面上的值先探一次，不保存 |
