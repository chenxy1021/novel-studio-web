# Novel Studio · 网文写作工作台

[简体中文](README.md) · [English](README.en.md)

面向中文长篇连载的个人写作工作台。它把「选题 → 大纲 → 设定 → 伏笔 → 细纲 → 正文 → 体检 → 存档 → 记忆回写」串成一条可回退的生产线，而不是又一个聊天框。

- **正文永远是磁盘上的 Markdown**：`chapters/NNN-标题.md`，随时能用任何编辑器打开。
- **设定、细纲、伏笔、记忆存 SQLite**：跨书统一管理，读写走同一套领域接口。
- **连续性是算出来的**：人物三态、离场名单、物品去向、伏笔收线都由账本推导，不靠模型记性。
- **体检分两层**：确定性规则离线可跑，AI 复检只对照固定清单逐项判定。

技术栈：Vue 3 + Pinia + Vite / FastAPI + SQLite。前身是 DeepSeek Harness 插件 `novel-studio`，现为独立 Web 应用。

## 快速开始

需要 Python ≥ 3.11、[uv](https://docs.astral.sh/uv/)、Node.js ≥ 18 和 npm。

```bash
./scripts/dev.sh          # 起 API + Web，Ctrl-C 一起停
./scripts/dev.sh open     # 起完打开浏览器
./scripts/dev.sh status   # 端口、健康检查、日志位置
./scripts/dev.sh stop     # 按端口停止（孤儿进程也能收）
```

- Web：<http://127.0.0.1:5180>
- API：<http://127.0.0.1:8010/api/ping>
- 日志与 pid 在 `.run/`（已 gitignore）。

也可以分开跑：

```bash
make api      # 后端（uv + uvicorn，8010）
make web      # 前端（Vite，5180）
make test     # 后端 pytest + 前端 vitest
make build    # 前端类型检查 + 生产构建
```

首次启动会自动执行 `uv sync` / `npm install`。模型配置在「设置」页填写，写入 `data/gateway.json`（已 gitignore，不会进仓库）。

## 创作流程

| 步骤 | 产出 | 说明 |
|---|---|---|
| 1. 选题 | 书名、简介、章数、每章字数 | 「换一批」会带上上一批的指纹，避免每轮收敛到同一套骨架 |
| 2. 大纲 + 世界观 | `outlineText` / `worldText` + 卷表 | 分卷按矛盾阶段切，卷长不固定；虐文模式自动套公式 |
| 3. 设定 | 人物、关系、信息差、势力、地点、物品、规则、力量体系、社会、历史、术语 | 只补空字段，不覆盖已有设定 |
| 4. 伏笔 | 核心 / 卷级 / 情节三层 | 回收章必须晚于埋设章；**没有伏笔不能写正文** |
| 5. 段落纲 | 每段 3–30 章（默认 10） | 目标、转折、节奏、现场、出场人物 |
| 6. 细纲 | 每章节拍、压力、开场/收束状态 | 先看细纲，再决定写不写正文 |
| 7. 正文 | `chapters/NNN-标题.md` | 流式生成，失败的章可单章重试或跳过 |
| 8. 审阅 | 体检、AI 复检、按技能改写 | 新稿回「待确认」，旧稿进废章 |
| 9. 存档 | 索引状态 + 记忆回写 | 一批全部存档后才把位置/物品/状态并回设定 |

开书面板一条龙：**选章 → 确认本批文风 → 选技能 → 看参考资料 → 逐章生成**。写作运行带 `runId` 并发保护，同一章不会被两个窗口同时写。

## 核心机制

### 人物三态与连续性

人物状态分三层，互不覆盖：

- **出场状态** `appearanceStatus` + `firstChapter`：第一次在正文出现时是什么状态。
- **当前状态** `status` + `statusAt` / `statusLog`：只写正文已经写到的状态，按章记流水。
- **退场与结局** `exitChapter`（已发生或计划）、`finalStatus`（结局状态）。

计划在第 76 章死亡的人，写第 56 章时显示「在场（第76章起死亡）」，不会被当成已经死了。还没登场的人显示「尚未登场」。存档回写只认章记忆里明确写下的生死去留，模型推测不算；退稿会把这一章的首次登场和死亡一起撤回。

### 规则四级

每条世界规则带 `enforce`：

| 级别 | 能不能破 | 代价 |
|---|---|---|
| 铁律 | 不能破，只能绕 | 破了世界或人物不成立 |
| 契约 | 能破 | 当场付明确代价（反噬、折寿、失忆、违约反扑） |
| 惯例 | 能破 | 社会性代价（被逐出、失信、得罪势力） |
| 谣言 | 人物以为成立 | 打破时揭示真相 |

规则另有 `cost`、`boundary`（何时不适用/漏洞）、`enforcer`（谁在执行）。力量体系的代价/上限**按题材可选**：黑暗流可以写「力量有价」，轻松爽文留空即可。

### 章节口径与数据安全

- 「写到第几章」只认 `chapters/index.json` 的最大章号（`written_through()`）。`project.currentChapter`、`gate.chapter` 都是派生值，补存档旧章不会把「下一章」拉回去。
- 删除整本书前，先把整个书目录复制到 `data/deleted/`，再删目录和数据库行。应用内没有恢复入口，但磁盘上留了完整副本。
- 正文被覆盖前，旧文件留在 `chapters/.versions/NNN/`，每章保留最近 20 份。

### 记忆

记忆是正文的派生数据：每章落盘后自动回写，改写后重算，写到卷末顺带更新卷摘要。

- 章记忆：故事内时间、地点、出场人物、关键事件、谁知道什么、关系变化；回忆章带 `isFlashback`。
- 卷摘要：主线、支线、关系、读者已知、下一卷、与大纲的偏差。
- 时间线：按章投影，只在记忆页维护；单条事件可标「回忆」。
- 回写失败不影响正文，只在记忆页留下缺口，可单章或批量补齐。
- 开着自动记忆时，**缺章记忆会拦住存档**（409 `memory-gap`），确认照存可 force。

`DSH_NOVEL_AUTO_MEMORY=0` 关闭自动回写（测试与离线环境用）。

### 体检与改写

- **确定性体检**（不调模型）：字数、平台格式、AI 痕迹（分类/次数/引文/段号与偏移）、章尾钩子、硬规则、离场人物复活。误报可以逐条「忽略」，不再计入也不再挡存档。
- **质量补充**：跨章六字复读、章内原样重复句、对话占比/句段节奏/用字多样性、细纲每一拍是否走完「谁→想要→受阻→结果」。
- **AI 语义复检**：只对照固定清单逐项判定（细纲必做/回避、伏笔埋收、物品地点势力对设定、硬规则、截至上一章的人物状态、与上一章结尾衔接、章内一致、限知视角）。判不过必须引用原句；清单全过才算通过。
- **按技能改写**：只改命中问题的段落，保留已发生事实与揭示顺序。落盘前重跑硬校验：正文过短、低于字数下限、撞规则、或节奏/对话/用字明显变平，都会拒绝落盘，旧稿一个字不动。
- 复检按轮走：刷新只摘掉已解决的条目，不重复问模型；整章改写或手动开新一轮才重判。
- 旧稿进「废章」，可恢复；退稿释放章号，可立刻重写同一章。

## 页面

侧栏按一天的用法分组：

| 组 | 页面 |
|---|---|
| 工作台 | **今日**（现在该做什么）、**开书**（流水线）、**文风**（书级默认 + 作家参照） |
| 写作 | **进度**（逐章审阅/体检/改写/存档）、**废章** |
| 规划 | **大纲**（结构大纲/世界观/地图）、**细纲**（段落纲 + 参考资料）、**伏笔** |
| 资料 | **人物**（人物卡/关系矩阵/关系图/位置轨迹）、**记忆**（时间线/前情/回查）、**设定**（规则/世界纵深/势力/地点/物品/信息差） |
| 系统 | **设置**（外观/自动存档/模型/修复/用量） |

外观三态：跟随系统 / 浅色 / 深色，token 用 `light-dark()` 一次定义，存在 `localStorage`。

## 参考资料包

细纲和正文生成前会打包实际注入的资料：本卷大纲、本章台阶、伏笔、人物卡（含别名/状态/关系）、规则、世界观、势力、地点、物品、力量体系、社会、历史、术语、位置与物品去向、信息差、近章记忆、卷摘要、时间线、上一章结尾、本章已离场名单、文风、平台打法。

`GET /api/projects/chapters/{n}/references` 返回与提示词一致的条目数和缺失项，供「本章资料」面板展示。超出字数预算时按相关度整条装入，装不下的折成一行名录，不会静默丢掉人物。

写正文前会做一次实体解析：从细纲、台阶、上一章记忆、近两章出场和作者强调里找出本章会用到的人/地/物/势力/术语/伏笔，每条带命中来源；作者可以在面板里逐条排除。

## 模型配置

写作走 OpenAI 兼容接口，配置跨书共用：

- 文件：`data/gateway.json`（`NOVEL_STUDIO_HOME` 可换目录）。
- 设置页：Base URL / 正文模型 / 轻活模型 /「测试连接」。
- 主要长文本生成都有 SSE 流式版本（选题、大纲、设定、伏笔、细纲、正文、改写）：`stage` 报阶段、`delta` 推增量、`reason` 推思考过程、`done` 带最终结果、`error` 统一错误。
- 思考强度按阶段路由：蓝图/概念/设定 `high`，细纲/伏笔/正文/改写 `medium`，记忆 `none`。可用 `NOVEL_STUDIO_REASONING='{"prose":"high"}'` 覆盖。
- 非流式正文接口支持 `candidates: 1–3`，写多稿后按字数、AI 痕迹和节奏挑一稿；界面默认走流式，因此默认为 1 稿。
- 模型回了不可解析的 JSON 时会做一次修复尝试（尾逗号、字符串内裸引号），设定类请求还会换一次请求重试。

同步接口保留，脚本和旧调用不受影响。

## 存储

| 数据 | 位置 |
|---|---|
| 书的设置、人物、世界观、势力/地点/物品/规则、文风 | SQLite：`data/studio.db` |
| 卷、细纲、段落纲、伏笔、章/卷记忆、人物状态、关系、时间线 | SQLite（同一文件） |
| 正文 | 书目录 `chapters/NNN-标题.md` |
| 章节索引 | `chapters/index.json` |
| 正文历史版本 | `chapters/.versions/NNN/*.md`（每章最近 20 份） |
| 提示词模块 | `prompts/*.md`；书目录下同名文件可覆盖 |
| 地图 / 关系图 | 书目录 `map.json` / `relation_map.json` |
| 兼容快照 | 书目录 `project.json` / `bible.json` |
| 删除前快照 | `data/deleted/` |

旧书首次读取会自动导入数据库；`ledger/*.jsonl` 第一次读时导入 `ledger` 表，文件保留作审计与导出。

## 环境变量

| 变量 | 作用 |
|---|---|
| `NOVEL_STUDIO_HOME` | 系统数据目录（SQLite / gateway.json / recent.json），默认 `<仓库>/data` |
| `DSH_NOVEL_HOME` | 书目根目录，默认 `~/Desktop/mine/xiaoshuo` |
| `DSH_NOVEL_ALLOWED_ROOTS` | 额外允许新建项目的位置（`:` 分隔） |
| `DSH_NOVEL_DB` | 只覆盖 SQLite 文件路径 |
| `DSH_NOVEL_RECENT_FILE` | 覆盖最近打开列表文件 |
| `DSH_NOVEL_AUTO_MEMORY` | `0` 关闭正文落盘后的自动记忆 |
| `NOVEL_STUDIO_SNAPSHOT_DIR` | 整本删除前的快照目录，默认 `<数据目录>/deleted` |
| `NOVEL_STUDIO_REASONING` | 按阶段覆盖思考强度，JSON |

## 目录结构

```text
backend/
  app/api/          # 路由：books / studio / review / memory / style / settings
  app/core/         # 数据目录、书稿路径、删书与快照
  app/store/        # 文件层 + SQLite 兼容路由（project、chapters、ledger、锁、原子写）
  app/domain/       # 领域层：writing、review、memory、continuity、quality、metrics、references…
  app/llm/          # OpenAI 兼容客户端、设置、阶段路由
  tests/            # pytest（含 golden 对照）
frontend/
  src/views/        # 13 个页面
  src/components/   # 写作面板、体检面板、记忆组件、命令面板…
  src/api/          # 后端数据 → 视图模型
  src/stores/       # 当前书、写作运行、记忆、体检、toast
  src/design/       # 主题 token + 组件库
prompts/            # 可复用的写作方法模块
```

## 测试

```bash
make test        # 后端 pytest + 前端 vitest
make test-store  # 只跑前端
```

后端测试默认全部离线（模型调用被替身接管），并使用临时数据目录与书柜，不碰真实数据。

## 快捷键

- `⌘K` / `Ctrl K`：命令面板，搜页面、章节、人物、伏笔和动作。
- `/` 打开命令面板；`?` 看全部快捷键；`T` 切主题；`W` 打开写作面板。
- `G` 后按 `H/P/X/O/D/F/M/W/C/S/,` 跳页面。
- 进度页：`J/K` 走章，`↵` 存档或展开，`R` 退回，`B` 按批体检。

## 状态

个人自用项目，界面和文案按中文网文写作习惯设计。领域层从旧插件的 `lib/*.js` 逐模块移植，关键模块有 golden 测试对照；`make test` 是提交前的验收门槛。
